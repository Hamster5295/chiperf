# chiperf 事件手册

**非规范性文档**：格式的权威定义在 [`spec.md`](spec.md)。这里回答的是另一个问题 ——
**每条记录该怎么写、什么时候该用哪一种、哪些地方容易写错**。

例子都可以直接粘进文件；带 ⚠️ 的段落是实践里真会踩的坑。

---

## 0. 每条记录共有的东西

### 0.1 记录的形状

```
<行首> [ <类型> ] <位置参数...> [ , <属性>... ] [ # 注释 ]
```

- **一条记录一行**，不许跨行；行尾必须有 `\n`（这是崩溃安全的前提：任意按行切断的文件都合法）。
- 位置参数在前、属性在后；**位置参数出现在属性之后 ⇒ 该行非法**。
- `#` 前**必须**有空白（或位于行首）才是注释 —— `bubble#x` 里那个 `#` 不是注释。
- 未知的 `[类型]` ⇒ 跳过该行并计数；未知的 `@指令` ⇒ 跳过；未知的**属性键** ⇒ 忽略该属性、其余照常解析。
- 域 = 记录所在的时钟域：每条记录都可用 `dom=` 指定，缺省 `default`。

### 0.2 通用属性

| 属性 | 值 | 作用 |
| --- | --- | --- |
| `dom=` | 域名（`sym`/`str`） | 这条记录属于哪个时钟域；缺省 `default` |
| `at=` | `int[p\|n]`，如 `42p`、`7n`、`9` | **显式指定位置**，覆盖"取该域当前周期"；相位字母缺省为 `p`。不推进时钟、不影响后续记录 |
| `async=` | `0` / `1` | 标为"不是时钟沿采样得到的"（外部中断、DMA 完成、异步握手回报…）。可视化把它画在周期区间**内部**而不是沿刻度上 |
| `note=` | 字符串 | 人类可读注解；对派生量没有影响 |

⚠️ `async=1` 只描述**采样方式**，不改变位置模型：它照样落在确定的 `(域, 周期, 相位)` 上、照样计入计数与占用度。
⚠️ 反过来，确实在时钟沿上采样到的记录**不要**标 `async` —— 否则读者会以为它不发生在沿上。
⚠️ `at=` 会打乱"每域位置非递减"的保证，只在后处理/采样场景用（同域混用 `clk` 与 `at=` 会产生 `at_clk_conflict` 诊断）。

### 0.3 值怎么写

每种记录的第 2 个位置参数（或载荷）都是"值"，六种写法：

| 写法 | 类型 | 例 |
| --- | --- | --- |
| 十进制整数 | `int` | `1234`、`-1` |
| 其它进制整数 | `int` | `0x1f`、`0b1010`、`0o17` |
| Verilog 字面量（可带宽度与 4 态位） | `bits` | `32'h8000_01d0`、`4'b10xz`、`8'hFF` |
| 实数 | `real` | `0.95`、`1.2e-3` |
| 字符串 | `str` | `"addi a0,a0,1"`（5 种转义：`\"` `\\` `\n` `\t` `\r`） |
| 裸词符号 | `sym` | `IDLE`、`FETCH`、`core.if` |

- 小写裸词 `x` / `z` 单独出现时是 **4 态标量**（未知 / 高阻）；大写 `X` / `Z` 是普通符号。
- 带单位的量（`1.5ns`、`800MHz`）**只能**出现在 `@domain` 的 `period=` / `freq=` 位置；写在别处 ⇒ 该行非法。
- 值的比较（"变没变"、"是不是同一个"）按**类型 + 规范形文本**：`32'h1` 与 `1` 不是同一个值，`8'h2a` 与 `8'h2A` 是。

### 0.4 文件骨架

```chiperf
chiperf 2.0                       # 版本行：写入者必须写，且在首行
@meta design="rv32i-core" tool="verilator" date="2026-09-15"
@domain core, period=1.0ns        # 声明时钟域（可选；声明了才能把周期换算成时间）
@domain mem, freq=800MHz, note="内存时钟"

[clk] p, dom=core                 # 从这里开始才是事件
[cnt] "core.retired"
@end                              # 正常结束标记（缺了会被判为"可能被截断"）
```

## 1. `clk` —— 时钟沿

**一句话**：推进某个域的周期计数。**每条记录 = 一个沿**。

```ebnf
clk = "clk" , <沿> , [ dom = <域> ] ;
<沿> ∈ { "p" , "n" }
```

| 位置参数 | 类型 | 必需 | 说明 |
| --- | --- | --- | --- |
| 1 | `sym` | 是 | `p` 上升沿 / `n` 下降沿（大小写敏感） |

**语义**：`p` 让该域的周期号 +1；`n` 进入同一周期的后半段。周期号只由 `p` 推进，`at=` 不会改它。

**什么时候用**：每个沿都写一条 —— 这是让所有事件有"第几个周期"这个坐标的唯一办法。
只想记上升沿也够（周期编号完整），但**同一个域内不要混用"只写 p"与"p/n 都写"**两种模式。

```chiperf
[clk] p                      # default 域第 1 个上升沿（周期 1）
[cnt] "core.retired"         # 这一拍发生的事，跟着上面那条沿
[clk] n                      # 同一周期的下半段
[clk] p, dom=core            # core 域独立计数，与 default 无关
```

⚠️ `clk` 的域名同样由 `dom=` 给出，**没有**"第一个参数是域"的特例。
⚠️ `clk` 上写 `async=1` 会被忽略并产生 `async_on_clk` 诊断（时钟沿本身不可能异步）。

## 2. `cnt` —— 计数器

**一句话**：让一个计数器累加（或直接置成某个值）。**每条记录 = 一次事件**。

```ebnf
cnt = "cnt" , <名> , [ <增量> ] ;
```

| 位置参数 | 类型 | 必需 | 说明 |
| --- | --- | --- | --- |
| 1 | 名字 | 是 | 计数器名 |
| 2 | `int` | 否 | 增量，缺省 `+1`，**可以为负** |

| 专属属性 | 值 | 说明 |
| --- | --- | --- |
| `abs` | `int` | **绝对值设置**：把累计值直接置为它（不贡献增量） |

**语义**：`total += delta`。所以 `[cnt] "core.retired"` 就是"又退休了一条"。
`abs=` 用于硬件计数器**回读**：清零重捕、溢出重载，或者周期性把寄存器的值抄下来。
`abs=` 与增量**不得同一条**出现（该行非法）。

**什么时候用**：你要的是"**一共多少次**"（以及每周期速率）。
只要"此刻发生了一次"而不要累计、或者要带个载荷，用 `evt`。

```chiperf
[cnt] "core.retired"                 # +1
[cnt] "core.retired", 4              # 一条指令退休了 4 次？不会 —— 这是"一次 +4"（例如 4 发射）
[cnt] "core.stall.mem", -1           # 允许负增量
[cnt] "core.cycles", abs=1234567     # 硬件计数器回读：总量置为 1234567
[cnt] "core.retired", dom="core"     # 归到 core 域（与 default 域的同名计数器是两条轨）
```

⚠️ `[cnt] "x", abs=5` 之后再来一条 `[cnt] "x"`，总量是 **6** —— `abs=` 只置总量，后续增量照加。
⚠️ 总量变负**不**判非法，只产生 `negative_total` 诊断。
⚠️ 同名计数器在不同域里是**两条独立轨迹**（追踪键 = `(域, 名字)`）。

## 3. `val` —— 数值采样

**一句话**：把某个信号的当前取值记下来；此后**一直保持**，直到下一次采样。

```ebnf
val = "val" , <名> , <值> ;
```

| 位置参数 | 类型 | 必需 | 说明 |
| --- | --- | --- | --- |
| 1 | 名字 | 是 | 数值名（建议层级路径，如 `core.if.pc`） |
| 2 | 任意标量 | 是 | 采样到的取值 |

**语义**：**保持型**。首个采样之前的值是"未知"；任意两次采样之间保持前一次的取值。

**什么时候用**：任何"这一拍这个信号是什么"的量 —— PC、指令字、命中率、温度、队列水位。
它刻意**只记变化点**：值没变就不用写（保持型替你省掉了重复行）。

```chiperf
[val] "core.if.pc", 32'h8000_01d0
[val] "core.id.instr", "addi a0,a0,1"    # 字符串值：反汇编文本、状态名
[val] "core.l1d.way", 4'b10xz            # 4 态：含有未知位/高阻位
[val] "core.ipc", 1.25                   # 实数
[val] "vdd", 0.95
```

⚠️ 想让可视化画出"每周期都在变"的阶梯，**不需要**每拍写一条；写出变化点即可，其余靠保持。
⚠️ `x`/`z` 参与比较：已知 → 未知、未知 → 已知都算"变化"。
⚠️ 想要"某个**事件**带一个载荷"（中断号、请求 ID）用 `evt`，不要用 `val`。

## 4. `pip` —— 在飞条目（流水级 / 缓冲 / 通道）

**一句话**：直接指定这个流水级**此刻的新取值**（`bubble` 表示变空）；没有记录就保持上一值。

```ebnf
pip = "pip" , <轨> , ( <值> | "bubble" ) ;
```

| 位置参数 | 类型 | 必需 | 说明 |
| --- | --- | --- | --- |
| 1 | 轨道名 | 是 | 建议层级路径：`core.if`、`core.mem.lsq` |
| 2 | 任意标量 / `bubble` | 是 | 该级**变成**的值；`bubble` 是保留裸词，表示该级没有内容 |

**语义**：保持型，与 `val` 同构 —— 跟"进 / 出 / 撤"配对没有关系了（v2.0 起）。

| 你写的 | 该级此后 |
| --- | --- |
| `[pip] "core.if", 0x1234abcd` | 持有它 —— 一个**在飞条目**从这里开始 |
| `[pip] "core.if", x` | 持有未知值（在飞，但内容未知） |
| `[pip] "core.if", bubble` | 空 —— **气泡**从这里开始 |
| （什么都不写） | 保持上一值不变 |

由此得到的读法：

- **条目** = 该级连续持有同一个值的那一段；它的**结束**是"下一条把它改成别的值（或 `bubble`）的记录"，**不需要也不存在**"出队"记录。
- **同一个值再写一次是空操作**（该级一直持有它）—— 因此没有"标记唯一性"这类要求。
- **首条记录之前**该级是"未开始"：既不是条目也不是气泡。
- **一个轨道同时只有一个当前值**。要表达"好几个条目同时在飞"（队列、多入口缓冲），用**多条轨道**。

**什么时候用**：任何"这一级/这个通道里现在装着什么"的部件 —— 五级流水的每一级、LSU 队列、
总线通道。条目驻留（`close - enter`）就是它的延迟分布来源。

```chiperf
[pip] "core.if", 0x1234abcd     # IF 开始持有这条内容
[pip] "core.id", 0x1234abcd     # 它到了 ID；IF 那条不动（要保持就什么都不写）
[pip] "core.if", bubble         # IF 空了（取指停顿；冲刷/取消也这么表达）
[pip] "core.mem", x             # 有内容但内容未知
[pip] "core.l2", 0x4000, dom="core"   # 跨时钟域轨道：起始在 core
[pip] "core.l2", bubble, dom="mem"    # …结束在 mem（该条目会被标记为 cross_domain）
```

⚠️ `I` / `O` / `X` 是 v1.x 的方向，现在**写在这个位置会被判非法**并给出一条迁移提示
（`pip_legacy_direction`）。`1.x` 的文件也会被拒绝，转换方式见 spec §12.5。
⚠️ **冲刷与正常离开在数据上不可区分** —— 两者都是"该级被设成别的值或 `bubble`"。
要区分就得另加 `evt`/`val` 或 `note=`。
⚠️ 同一条内容跨级出现时，**把值写成一样**（例如都用指令 PC）：可视化按取值着色，
一眼能顺着颜色把它从 IF 跟到 WB。
⚠️ 轨道键**只有轨道名**（不含域）：`core.l2` 在 core 域与 mem 域的记录属于**同一条**轨道。

## 5. `fsm` —— 状态机

**一句话**：把状态机的当前状态记下来；保持型。

```ebnf
fsm = "fsm" , <名> , <状态> ;
```

| 位置参数 | 类型 | 必需 | 说明 |
| --- | --- | --- | --- |
| 1 | 名字 | 是 | 状态机名，如 `core.ctrl` |
| 2 | `sym` / `str` / `int` | 是 | 当前状态 |

**语义**：保持型（与 `val` 相同）；首个记录之前是 `unknown`。
相邻两条记录构成一次跳转 `from → to`；`from == to` 就是**自环**（合法，会产生 `self_transition` 诊断，
可视化按"驻留"合并显示）。

**什么时候用**：控制器、cache 的 FSM、握手状态。它比 `val` 多的是**跳转表**与**驻留统计**
（每个状态待了多少周期、转移图长什么样）。

```chiperf
[fsm] "core.ctrl", IDLE
[fsm] "core.ctrl", FETCH
[fsm] "core.ctrl", FETCH        # 自环：状态没变但被再次断言（可视化合并成一段驻留）
[fsm] "core.icache.ctrl", 3     # 状态也可以是数字或字符串
```

⚠️ 只在**状态变化时**写就够（保持型）；重复写同一个状态等于一次自环，会产生诊断。
⚠️ 同一个名字同时当 `fsm` 与 `val`/`cnt` 用会被记 `name_reused`（解析器接受，但可视化无从判断该画哪种）。

## 6. `evt` —— 瞬时事件

**一句话**：记一次"发生了这件事"，可以带一个载荷；**不保持、不累加**。

```ebnf
evt = "evt" , <名> , [ <载荷> ] ;
```

| 位置参数 | 类型 | 必需 | 说明 |
| --- | --- | --- | --- |
| 1 | 名字 | 是 | 事件名 |
| 2 | 任意标量 | 否 | 载荷（中断号、请求 ID、地址…） |

**语义**：瞬时。与 `cnt` 的区别在**意图**：`cnt` 是"这是个累加器"，`evt` 是"这是一次离散标记"。
可视化对 `evt` 给事件点与载荷分布；计数器页也可以把每条 `evt` 当"每次 +1"折成一条计数曲线看。

**什么时候用**：中断到达、重定向发生、清空/刷新完成、模式切换 —— 任何"点上的一次通知"。
标注性文字用 `msg`，不要用 `evt`。

```chiperf
[evt] "core.redirect", 0x80000100          # 带载荷：跳到哪里
[evt] "irq.assert", 7, async=1             # 异步到达：画在两个沿之间
[evt] "reset.released"
[evt] "tlb.way", 2, note="demand miss"     # 注解放在 note=，不要拼进名字
```

⚠️ 别把变化的量塞进名字（`[evt] "irq5"`、`"core.rob[17]"`）：名字要在插桩**设计时**固定，
否则追踪对象数会随仿真时间增长。
⚠️ 与计数器重名会被记 `name_reused`。

## 7. `msg` —— 自由文本

**一句话**：写给人看的一行注解。

```ebnf
msg = "msg" , <文本>
```

- `<文本>` = `msg` 之后直到行尾的全部内容（去首尾空白）。**不解析**逗号、属性与注释。
- 若整段恰好是一个合法字符串字面量（`"..."`），解析器会剥掉引号并解码转义。

**什么时候用**：仿真开始/结束、模式切换、已知异常的说明；工具产生的"文件说明"行。

```chiperf
[msg] reset released, starting trace
[msg] "entering turbo mode"
[msg] simulated 1e6 cycles; see note #3 in the README     # 整个 "simulated … README" 都是正文
```

⚠️ `msg` **不支持任何属性**：`dom=`、`at=`、`async=`、`note=` 都会被当成正文的一部分。
需要带定位/标记的注解就用 `evt` + `note=`。
⚠️ 因为"取正文"发生在剥注释**之前**，`[msg] a # b` 的正文是 `a # b`（那个 `#` 不是注释）。

## 8. `rst` —— 系统复位（控制记录）

**一句话**：丢弃这行**之前**的全部事件记录，从这一行重新开始。

```ebnf
rst = "rst" ;
```

| 方面 | 规定 |
| --- | --- |
| 丢弃什么 | 此前全部**事件记录**及其派生量（在飞条目、计数累计、数值保持、状态机状态、气泡/占用统计） |
| 保留什么 | 版本行与 `@` 指令（它们是**声明**不是行）：域集合、`period`/`freq` 换算继续有效 |
| 周期号 | **不重编**：复位后接着原来的周期号往下排（时钟不会回到 0） |
| 可视化 | `rst` 不占位置、不占 `seq`、不进任何泳道；只在头部显示一个信息 chip |
| 参数 | **不允许**任何参数或属性（`dom=`/`at=`/`async=` 都不行） |

**什么时候用**：仿真前有一段"热身/初始化"想从图里去掉时，在复位释放处写一条。

```chiperf
chiperf 2.0
[clk] p
[cnt] "cold.reset.warmup"          # 这一段之后会被丢掉
[clk] n
[rst]                              # 从这行起，前面的记录当作没发生过
[clk] p
[cnt] "core.retired"               # 复位后重新开始累计
@end
```

⚠️ 复位处正在飞的条目随之销毁：复位后该级回到"未开始"，直到下一条 `[pip]` 重新设值。
复位后紧接着写 `[pip] "core.if", bubble` 也很正常 —— 那只是"该级变空"。

## 9. 选型：我该用哪个？

| 我想表达 | 用它 | 为什么不是别的 |
| --- | --- | --- |
| "此刻发生了第 N 次" | `cnt` | `evt` 不累加；`val` 是保持型 |
| "这一刻发生了一件事，附带一个载荷" | `evt` | `cnt` 的载荷位置是增量，语义不同 |
| "这个信号/指标现在是多少" | `val` | 保持型，只写变化点即可 |
| "这一级现在装着什么" | `pip` | 多出"条目/气泡/驻留"这层语义；`val` 没有 |
| "状态机现在在哪个状态" | `fsm` | 多出跳转表、自环、驻留统计 |
| "给人看的一句话" | `msg` | 不参与任何派生量 |
| "推进时钟" | `clk` | 只有它能推进周期号（`at=` 只是覆盖单条记录的位置） |
| "把之前的记录丢掉" | `rst` | 控制记录，不是事件 |

## 10. 常见写法模板

### 10.1 每个沿都写（推荐）

```chiperf
[clk] p
[val] "core.if.pc", 32'h8000_0000
[cnt] "core.icache.access"
[pip] "core.if", 0x80000000
[clk] n
```

### 10.2 只写上升沿

```chiperf
[clk] p
[cnt] "core.retired"
[clk] p
[cnt] "core.retired", 2
```

### 10.3 多时钟域

```chiperf
@domain core, period=1.0ns
@domain mem, freq=800MHz
[clk] p, dom=core
[cnt] "core.retired", dom="core"
[clk] p, dom=mem
[cnt] "mem.access", dom="mem"
```

### 10.4 后处理 / 采样器（没有时钟记录，全靠 `at=`）


## 11. 一眼对照表

| 类型 | 语义 | 位置参数 | 专属属性 | 一句话 |
| --- | --- | --- | --- | --- |
| `clk` | 推进时间 | `<沿>` | —— | `p` = 一个周期 |
| `cnt` | 累加 | `<名>[, <增量>]` | `abs=` | 又发生了一次 |
| `val` | **保持** | `<名>, <值>` | —— | 这个信号现在是多少 |
| `pip` | **保持** | `<轨>, <值\|bubble>` | —— | 这一级现在装着什么 |
| `fsm` | **保持** | `<名>, <状态>` | —— | 状态机现在在哪儿 |
| `evt` | 瞬时 | `<名>[, <载荷>]` | —— | 发生了一件事（带载荷） |
| `msg` | —— | `<行尾文本>` | —— | 给人看的一句话 |
| `rst` | 控制 | 无 | —— | 之前的记录不要了 |
