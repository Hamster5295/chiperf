# Chiperf Spec v1.0

- 版本：`1.0`
- 状态：已冻结（本期交付）
- 关键词：本文中的 **必须 (MUST)**、**不得 (MUST NOT)**、**应当 (SHOULD)**、**不应当 (SHOULD NOT)**、**可以 (MAY)** 按 RFC 2119 解释。

---

## 1. 简介

chiperf 是一种**文本、事件驱动**的硬件微架构性能轨迹格式。它由 RTL 仿真期的插桩代码按"写文件"的方式生成：在每个有意义的时钟沿上，向文件追加一行记录；一条记录描述一件事（一次时钟沿、一次事件计数、一次数值变化、一次流水线进出、一次状态机跳转）。

chiperf 的核心读者是**解析器**：文件由仿真插桩程序写、由工具链批量读，人类偶尔打开只是辅助。因此本规范的取舍原则是 **解析器优先（parser-first）**：语法要能单遍流式解析、不需要跨行状态、不需要回读；人类可读性（纯文本、名字内联、`#` 注释）是顺带保留的好处，而不是必须满足的指标。

chiperf 的目标不是替代波形数据库（VCD/FST），而是给 RTL 工程师一个**低成本、易解析、可增量写、坏了也不怕**的性能记录通道：

| 目标 | 手段 |
| --- | --- |
| 事件驱动 | 只有发生的事才占文件空间；没有波形 dump 的固定采样率开销 |
| 解析器优先 | 单遍流式解析；记录自包含、无跨行状态；一种概念只有一种写法（见 §1.1） |
| 鲁棒 | 行式记录 + 记录自包含 ⇒ 任意"按行切断"的前缀都是合法文件（见 §10.1） |
| 可视化 | 每类记录对应一种稳定的可视化语义（见 §9） |
| 可扩展 | 未知记录类型/属性/指令必须被忽略而非报错（见 §12） |

非目标（v1.0 明确不做）：

- 不做信号的逐周期全量 dump（那是 VCD/FST 的活）。
- 不描述电路结构、网表、层次化 instance 树（层次只体现在名字字符串里）。
- 不做握手/依赖关系建模（`req`/`ack`/`stall` 因果关系），见 §12.4 的演进预留。
- 不规定可视化的视觉形式（颜色、布局），只规定语义。

### 1.1 解析器优先原则的具体后果

| 决策 | 原因 |
| --- | --- |
| 一条记录只占一行，且记录自包含 | 可以单遍流式解析；出错只需丢弃一行（§10.3） |
| 所有跨记录状态都是"派生"而非"声明" | 任意行边界前缀都合法（§10.1） |
| 一种概念只有一种写法（不做同义拼写） | 解析器不需要做拼写归一化 |
| 周期号由 `clk` 记录隐式推进，而不是每条记录都写一遍 | 文件更小；解析器每域只维护两个整数 |
| `dom=` 是唯一的域指定方式 | `clk` 不再有"参数个数决定语义"的特例（§7.1） |
| 数值自带进制与 4 态（`x`/`z`） | 解析器不做二次推断，RTL 语义直接落盘 |
| 词法只有两处上下文相关（`at=` 的值、`msg` 的载荷），其余上下文无关 | 词法可以一次扫描完成；不存在"以 `=` 开头的数值"这类特例（§5.1） |
| 写入者必须按**每域**位置非递减顺序输出 | 解析器可边读边出，不必缓冲重排（§6.3） |
| 版本行由写入者强制写出，但解析器容忍缺失 | 新文件自描述；老文件与手写片段仍能解析（§5.4） |

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| **记录 (record)** | 文件中的一行，分三类：指令行、事件行、注释行 |
| **事件 (event)** | 一条描述"发生了什么"的记录，形如 `[...]` |
| **指令 (directive)** | 一条描述"文件自身"的记录，形如 `@...` |
| **域 (domain)** | 一条独立的时间轴，通常对应一个时钟。默认域名 `default` |
| **周期 (cycle)** | 域内相邻两个**上升沿**之间的区间；从 1 开始编号 |
| **相位 (phase)** | 周期内的位置：`p`（上升沿之后）、`n`（下降沿之后）或 `-`（尚无时钟） |
| **位置 (position)** | 一条事件被定位到的 `(域, 周期, 相位, 序号)` 四元组，见 §6.3 |
| **轨道 (track)** | `pip` 事件的命名实体，对应流水级/缓冲/通道这类"同一时刻持有一个内容"的部件 |
| **在飞条目 (in-flight item)** | 轨道当前**持有**某个值的那一段时间；该级被设成别的值（或 `bubble`）时它结束 |
| **派生量 (derived quantity)** | 由事件流计算出来的量（占用度、延迟、计数总量、状态时长……），见 §9 |

## 3. 文件容器与编码

### 3.1 后缀

| 后缀 | 含义 |
| --- | --- |
| `.chiperf` | 纯文本 chiperf 流 |
| `.chiperf.gz` | gzip 容器（RFC 1952），解压后即 `.chiperf` 的字节流 |

- 写入者 **不得** 在 `.chiperf` 之外再做额外包装（tar/xz/zip 等）；需要压缩时只能使用 gzip。
- 解析器 **必须** 通过后缀**或**前两字节魔数 `1f 8b` 判定 gzip；两者冲突时以魔数为准。
- gzip 容器 **应当** 只包含一个成员。多成员 gzip 流（如 `cat a.chiperf.gz b.chiperf.gz`）**可以** 出现，解析器 **必须** 按成员顺序依次解压并拼接成**单一** chiperf 事件流；拼接 **必须** 在按行切分**之前** 完成（成员边界不保证与行边界对齐）。

### 3.2 字符编码

- 内容 **必须** 是 UTF-8。解析器 **应当** 用替换字符（U+FFFD）容错非法字节，而不是丢弃整个文件。
- 名称、字符串字段允许任意 Unicode 字符（含中文）。
- 行终止符为 `\n`（LF）。解析器 **必须** 接受 `\r\n`（CRLF）并剥除行尾 `\r`。写入者 **应当** 只写 LF。

### 3.3 文件结尾

- 正常结束的轨迹 **必须** 由写入者以 `@end` 指令收尾（见 §8.3）。
- 没有 `@end` 的 EOF 也是合法结尾；解析器 **必须** 将其标记为"可能被截断"（`eof_without_end_marker` 诊断），而 **不得** 因此拒绝文件。
- 空文件、只有版本行/指令/注释的文件均为合法（空轨迹），且 **不得** 产生 `eof_without_end_marker`（没有任何内容被截断）。

## 4. 词法

逐行解析。行内从左到右扫描，记号的识别优先顺序为：**字符串 → 数值 → 裸词**。

### 4.1 空白与注释

- `sp` = 空格与制表符的任意序列（含空）。
- 行首 `sp` 与行尾 `sp` **必须** 被忽略。
- 注释：`#` 到行尾。`#` **必须** 位于行首（允许前置空白）或前面有一个空白字符。字符串内部的 `#` 不是注释。
- 空行（只有空白）**必须** 被忽略。

```chiperf
# 整行注释
[cnt] "L2 Miss"   # 行尾注释也允许
```

### 4.2 字符串

```ebnf
string  = '"' , { sp-char | escape } , '"' ;
escape  = "\" , ( "\" | '"' | "n" | "t" | "r" ) ;
```

- 转义序列仅限 `\\`、`\"`、`\n`、`\t`、`\r` 五种。出现其它转义（如 `\q`）时的记录：
  - 写入者 **不得** 使用。
  - 解析器 **应当** 按"字面字符"容错（`\q` → `q`）并产生诊断，而不是丢弃整条记录。
- 字符串 **不得** 跨行；写入者 **不得** 在字符串里写裸 LF（用 `\n`）。
- 字符串**未闭合**时（行尾到达仍无 `"`），该记录非法（见 §10.3）。

### 4.3 数值

```ebnf
number     = [ "-" ] , num-body , [ unit ] ;
num-body   = int , [ "." , int ] , [ ( "e" | "E" ) , [ "+" | "-" ] , int ]   (* 十进制整数/实数 *)
           | ( "0x" | "0X" ) , hexdigits
           | ( "0b" | "0B" ) , bindigits
           | ( "0o" | "0O" ) , octdigits
           | [ int ] , "'" , [ "s" ] , base , basedigits                     (* Verilog 风格 *)
;
base       = "b" | "o" | "d" | "h" ;
digits     = { digit | "_" } ;
hexdigits  = { hexdigit | "_" | "x" | "X" | "z" | "Z" } ;
bindigits  = { "0" | "1" | "_" | "x" | "X" | "z" | "Z" } ;
octdigits  = { "0".."7" | "_" | "x" | "X" | "z" | "Z" } ;
basedigits = { hexdigit | "_" | "x" | "X" | "z" | "Z" } ;
unit       = ( "s" | "ms" | "us" | "ns" | "ps" ) | ( "Hz" | "kHz" | "MHz" | "GHz" ) ;
```

- 各类进制字面量内部 **可以** 用 `_` 分隔，解析器 **必须** 忽略 `_`。
- 4 态：`0x`/`0b`/`0o` 与 Verilog 字面量的数字位中 **可以** 出现 `x`/`z`（大小写均可），表示未知位 / 高阻位。
  - 例：`4'b10xz`、`8'bx`、`32'hz`、`0b1x0z`。
- Verilog 字面量 `<size>'<s><base><digits>` 的 `size` **可以** 省略（此时宽度未指定）：`'hFF` 合法。
- `-` 前置于任意数值字面量，对整个字面量取负。写入者 **应当** 只在表示有符号量时使用。
- **缩放量**（带单位）仅在 `@domain` 的 `period=` / `freq=` 属性中合法，其它位置的缩放量记录为非法。

### 4.4 裸词（bare word）

```ebnf
word      = wordchar , { wordchar } ;
wordchar  = A-Z a-z 0-9 | "_" | "." | "$" | "+" | "-" | "/" | "[" | "]" ;
```

- 裸词用于：记录类型名、属性键、符号值（如 FSM 状态名 `IDLE`）与 `[pip]` 的保留词 `bubble`。
- 裸词**不得**包含空白、`,`、`=`、`"`、`#`。
- 名字里含空格或其它特殊字符时 **必须** 用字符串形式：`[cnt] "Cache Miss (L1D)"`。
- 字符串形式与裸词形式解析出的**名字字符串**相同：`[fsm] ctrl, IDLE` 与 `[fsm] "ctrl", "IDLE"` 指向同一个状态机与同一个状态。
- 但作为**值**时二者的类型不同：裸词是 `sym`，字符串是 `str`（§4.5）。需要 `sym` 语义的字段（`clk` 的沿、`cnt` 的增量）**不得** 用字符串形式书写。

### 4.5 值的语义类型

解析器 **必须** 为每个值字段标注以下类型之一：

| 类型 | 触发条件 | 例子 |
| --- | --- | --- |
| `int` | 无 `x`/`z` 位的数值 | `1234`、`0x8000_01d0`、`-3`、`32'hdeadbeef` |
| `bits` | 含 `x`/`z` 位的数值，或裸词 `x`/`z` | `4'b10xz`、`x` |
| `real` | 含 `.` 或指数的十进制数 | `1.5e-9` |
| `str` | 字符串 | `"addi a0,a0,1"` |
| `sym` | 其它裸词 | `IDLE`、`FETCH` |

- **裸词 `x`/`z` 规则（与记录类型无关，统一适用）**：任何**恰好**是 `x` 或 `z`（**小写**）的裸词，一律解析为 4 态标量（未知 / 高阻），类型为 `bits`，宽度未指定。
  - 大写 `X` / `Z` **不是** 4 态标量，而是普通符号：4 态只认小写 `x`/`z`，于是符号值与 4 态标量可以共存，不需要任何按类型分支的词法规则。
  - 数值字面量**内部**的 `x`/`z` 位不受此限，大小写均可（`4'b10XZ` 与 `4'b10xz` 等价，§4.3）。
  - 若某处确实需要一个名叫 `x` 的符号，**必须** 写成字符串 `"x"`（此时类型为 `str`）。
- 数值 **可以** 超过 64 位；解析器 **应当** 支持任意精度整数，**必须** 至少支持 64 位带符号整数与 64 位无符号整数。

## 5. 记录语法

### 5.1 EBNF

```ebnf
file        = [ version ] , { line } ;
version     = sp , "chiperf" , sp1 , digit , { digit } , "." , digit , { digit } , [ sp , comment ] , nl ;
line        = [ sp ] , body , [ sp ] , [ comment ] , nl
            | [ sp ] , nl ;
body        = directive | event ;
directive   = "@" , word , [ sp1 , args ] ;
event       = "[" , word , "]" , [ sp1 , args ] ;
args        = arg , { sp , "," , sp , arg } ;
arg         = value | key , sp , "=" , sp , value ;
key         = word ;
value       = string | number | word ;
comment     = "#" , { any-char-except-nl } ;
sp          = { " " | "\t" } ;
sp1         = ( " " | "\t" ) , sp ;
nl          = "\n" | "\r\n" ;
```

- 记录类型名（`word`）**必须** 全小写；未知类型的记录被跳过（§10.2）。
- `line` 产生式中的 `[ sp ] [ comment ]` **不适用** 于 `msg`：`msg` 的载荷是行尾原文，见 §7.7 与 §5.1 的第 3 条上下文规则。
- `,` 是唯一的字段分隔符；字段间 **可以** 有任意空白。
- 不允许空字段：`[cnt] "x",` 非法；`[cnt] ,` 非法。
- 参数 **必须** 出现在属性（`key=value`）之前；属性之间顺序任意。参数出现在属性之后 ⇒ 该记录非法。

规范里有**三条上下文相关规则**，加一条通用消歧规则：

1. **属性 vs 参数**（通用消歧）：字段首记号之后（允许空白）紧跟 `=` ⇒ 该字段是属性；否则是参数。因此 `[fsm] a, b` 是两个参数，`[fsm] a, b=c` 是参数 + 属性。
2. **`at=` 的值是一个整体记号**：从 `at=` 之后到下一个 `,`、空白或行尾之间的连续字符构成**单个记号**，其内容 **必须** 匹配 `int[p|n]`（数字与相位字母之间不得有空白）。这是词法层唯一与字段名相关的规则，作用域仅限 `at=` 的值。
3. **`msg` 的载荷是行尾原文**：`msg` 不按 `args` 解析，载荷取到行尾且其中的 `,`、`#`、`=` 都是普通字符（§7.7）；该行 **不得** 再按 §4.1 剥除注释。
4. **指令字段的分隔符更宽**：记录（`[...]`）的字段只认逗号；指令（`@`）的字段 **逗号或空白都可以** —— `@meta design="x" tool="y"` 与 `@domain core, period=1.0ns` 两种写法都在用，等价。未加引号的记号本就不含空白，所以没有歧义；指令里 `, ` 这种连续分隔符产生的空段按"没有这个字段"处理（记录里则是非法，见 §5.1 首段）。

除这两处（`at=` 的值、`msg` 的载荷）外，词法完全上下文无关：不存在"以 `=` 开头的数值"这类形式；一切绝对值/开关式需求 **必须** 用属性表达（如 §7.2 的 `abs=`）。

### 5.2 属性

属性是 `键=值` 形式的字段。v1.0 定义如下键，所有事件类型均可使用：

| 键 | 值类型 | 含义 |
| --- | --- | --- |
| `dom` | `sym`/`str` | 该记录所属时钟域；缺省为 `default` |
| `at` | `<int>[p\|n]` | 显式覆盖该记录的位置周期/相位；缺省相位为 `p` |
| `async` | `int`（`0`/`1`） | `1` = 该事件**不是时钟沿采样**得到的，落在当前周期/相位区间**内部**；缺省或 `0` = 沿对齐。见 §6.7 |
| `note` | `str`/`sym` | 自由注释，可视化 **可以** 作为提示显示 |

- **未知属性键必须被忽略**（不得判为非法）；解析器 **应当** 保留它们以便前瞻兼容。
- 同名属性重复出现时，**最后一条生效**，并产生 `duplicate_attribute` 诊断。
- `at` 的值按 `int [p|n]` 解析：数字与相位字母之间 **不得** 有空白（`at=1234p`）。相位字母省略时为 `p`。
- `at` **必须** 只影响该条记录的位置，**不得** 影响其域的周期计数与当前相位（见 §6.4）。同一域内既写 `clk` 又用 `at=` 会让"位置"与"周期计数"脱节，解析器 **必须** 产生 `at_clk_conflict` 诊断（§10.4）。

### 5.3 事件类型总览

| 类型 | 追踪能力 | 作用 | 参数 |
| --- | --- | --- | --- |
| `clk` | 时钟 | 声明一个时钟沿 | `<边沿>[, dom=<时钟域>]` |
| `cnt` | 事件次数 | 计数器的增减或绝对值设置 | `<名字>[, <增量>]` |
| `val` | 数值变化 | 数值采样（保持型） | `<名字>, <值>` |
| `pip` | 模块内内容 | 直接指定该级的新取值，或 `bubble` 表示变空（保持型） | `<轨>, <值 \| bubble>` |
| `fsm` | 状态机 | 状态机当前状态 | `<名字>, <状态>` |
| `evt` | 事件次数（带载荷） | 瞬时命名事件，可选载荷 | `<名字>[, <载荷>]` |
| `msg` | —— | 人类可读的自由文本 | 行尾剩余文本 |
| `rst` | —— | 系统复位：丢弃此前全部事件记录 | 无（**不允许** 任何参数） |

### 5.4 版本行

```chiperf
chiperf 1.0
```

- 版本行 **必须** 由写入者写出（解析器据此判定版本），且 **必须** 是文件的第一行（允许前置空白）。
- 版本行缺失时，解析器 **必须** 接受该文件并按 `1.0` 解释 —— 这是为手写片段保留的容忍度，不是写入者的选项（§1.1）。
- 同文件其它位置出现版本行 ⇒ 该行非法（§10.3，计 `skipped_invalid_record`）：它既不是指令也不是事件，不占 `seq`。
- 次版本号用于兼容性标注（"这一行用了哪个次版本才有的东西"）；解析器 **必须** 接受未知的次版本号（`1.7` 按 `1.x` 解析）；**必须** 在默认模式下拒绝其它主版本号（`2.0` 及以后），**可以** 提供显式的"忽略版本"模式。
- 本版本（`1.0`）是规范的第一个正式版本：`[pip]` 在这里定为**保持型取值**（§7.4）。更早的**草案**用过"`I` 进 / `O` 出 / `X` 撤"的配对写法，两者版本号相同但语义不同 —— 因此解析器**不能**靠版本号分辨，而是**必须**把落在 `[pip]` 值位置上的 `I`/`O`/`X` 判为非法记录，并给出迁移提示（`pip_legacy_direction`，§10.4.1）。

## 6. 时间模型

### 6.1 域

- 文件可以包含多个域，每个域是一条独立的时间轴，通常对应一个时钟。
- 默认域名为 `default`。名字 `default` 不需要声明。
- 域的建立方式：`@domain` 指令（§8.2）显式声明，或由任何记录的 `dom=` 隐式建立（含 `[clk]`）。
- 引用未声明域名的记录 **必须** 被接受：该域被隐式建立，周期从 0 起算。

### 6.2 时钟沿语义

`clk` 是唯一推进时间的记录。每个域独立维护：

| 状态 | 初值 | 更新规则 |
| --- | --- | --- |
| `cycles[d]` | `0` | 收到 `[clk] p, dom=d` 时 `+1`；`n` 不改变它 |
| `phase[d]` | `-` | `p` → `p`；`n` → `n` |

形式化规则（`p` = 上升沿，`n` = 下降沿）：

1. `[clk] p, dom=d`：`cycles[d] += 1`，`phase[d] = p`。**每个 `p` 记录都开启一个新周期**，无论当前相位是什么。
2. `[clk] n, dom=d`：`cycles[d]` 不变，`phase[d] = n`。
3. 因此"连续两个 `p` 之间没有 `n`"是合法的：只要上升沿的插桩就足以定义周期编号（常见的省事写法）。
4. 相位已经是 `n` 时再来一条 `n`：合法，相位不变，产生 `redundant_edge` 诊断（可能是重复插桩）。
5. 周期 `k` 定义为区间 `[第 k 个上升沿, 第 k+1 个上升沿)`；该区间内先经历相位 `p`（高电平段），再经历相位 `n`（低电平段）。

```text
        ┌────────┐            ┌────────┐
clk ────┘        └────────────┘        └────
        ↑        ↑            ↑
      [clk] p  [clk] n      [clk] p
      cycle k  cycle k      cycle k+1
      phase p  phase n      phase p
```

### 6.3 事件位置

每条事件记录被定位到 `(domain, cycle, phase, seq)`：

| 分量 | 取值 |
| --- | --- |
| `domain` | 记录的 `dom=` 属性，缺省 `default` |
| `cycle` | `at=` 给出的周期；否则 `cycles[domain]` |
| `phase` | `at=` 给出的相位；否则 `phase[domain]` |
| `seq` | 全局自增序号，从 1 开始，**每条被接受的事件记录**（含 `clk`）递增 1；指令与注释不占号，被跳过的非法记录（§10.3）与被忽略的未知类型（§10.2）也不占号 |

- 时钟之前（尚无任何 `p` 与 `n`）的事件位于 `cycle = 0`、`phase = "-"`。这类事件合法，用于记录复位/初始化阶段。
- 同一位置内的先后顺序 **必须** 按 `seq` 判定（即文件顺序）。
- **单调性是每域独立约束**：在同一域内，记录的位置 **必须** 按 `(cycle, phase)` 非递减（相位序 `p < n`）；**跨域不作任何位置比较** —— 不同域的"周期 5"没有可比性，跨域的先后只由文件顺序（`seq`）定义。
- 写入者 **必须** 按"每域位置非递减"写出记录，**除非** 使用了 `at=` 显式定位。
- 解析器 **必须** 接受任意顺序的输入（`at=` 允许乱序补写）；对不含 `at=` 的文件，解析器 **可以** 依赖**每域位置单调性**做单遍流式处理，不必缓冲重排。
- 内部表示：`seq`、每域 `cycles`、`at=` 的周期号 **必须** 至少用 64 位表示（长轨迹下会超过 32 位）。
- 若某域完全没有 `clk` 记录、但事件带 `at=`，该域的时间轴完全由 `at=` 定义（"无时钟模式"，见 §6.6）。

### 6.4 `at=` 的边界

- `at=` 只覆盖**单条记录**的位置。
- 它**不得**推进或回退 `cycles[]`、**不得**改变 `phase[]`、**不得**影响后续记录的默认位置、**不得**触发任何 `clk` 语义。
- 使用 `at=` 的记录同样占用 `seq`（用于同位置内的稳定排序）。

### 6.5 跨域

- 规则：任何事件都可以用 `dom=` 指定域；位置按该域计算。
- 同一轨道的记录 **可以** 落在不同域（例如跨时钟域 FIFO 的"进入"与"变空"分别由两端时钟域记录）。此时：
  - 解析器 **必须** 同时保留两端的 `(domain, cycle, phase)`；
  - **必须** 把该条目标记为 `cross_domain`；
  - **不得** 直接给出以"周期"为单位的驻留（跨域的周期数不可相减）；替代量见 §9.4 的 `latency_time`。

### 6.6 无时钟模式（clk-free）

- 定义：某域没有任何 `clk` 记录，全部事件用 `at=` 显式定位。
- 典型来源：**硬件采样器**（每 N 个周期回读一次性能计数器）与**后处理工具**（把别的格式转成 chiperf）。二者都是正常用法，不是例外。
- 该模式下 `cycles[d]` 恒为 `0`、`phase[d]` 恒为 `-`；事件位置完全由 `at=` 给出（相位缺省 `p`）。
- 解析器 **不得** 因某域没有 `clk` 记录而拒绝文件，也 **不得** 依据 `at=` 去推进 `cycles[d]`。
- 合规写入者 **必须** 保证同一域内 `at=` 的周期非递减。

### 6.7 异步事件（`async=`）

- 语法：任何事件记录 **可以** 带属性 `async=1`（`async=0` 或缺失 = 沿对齐，即该事件在记录的时钟沿上采样）。
- 语义：该事件**不是由时钟沿采样得到的**，它发生在"当前域、当前周期、当前相位"所定义的区间**内部**。
- **位置模型不变**：`async=1` 的记录仍有确定的 `(域, 周期, 相位, seq)`；`async` 与 `at=` 正交 —— 先按 `at=`/时钟状态定位到区间，再由 `async` 决定画在区间内部还是沿刻度上。
- **派生量不变**：延迟、占用度、计数、保持型取值都按同一套定义计算。区间归属已经确定，所以 `async` 只回答"这个事件画在哪里"，不改变"它算在哪一个周期"。
- 可视化 **必须** 把 `async=1` 的事件画在区间内部（两个相邻时钟沿**之间**），**不得** 吸附到上升沿/下降沿的刻度上；同一区间内的多个异步事件按 `seq` 排列。**应当** 使用与沿对齐事件不同的样式（如空心标记/虚线），让"这个数不是在沿上采的"一眼可见。
- 一个区间里可以同时有沿对齐事件与异步事件：例如"上升沿采样的计数"与"低相位里到达的中断"同属一个周期，但画法不同。这也正是 `cnt`/`val` 的采样继续保持型/累加语义、不需要为 `async` 单独定义的原因。
- `clk` 记录 **不得** 带 `async=1`：时钟沿本身不可能异步。解析器 **必须** 保留该记录（它仍是一条合法的沿）但忽略该属性，并产生 `async_on_clk` 诊断（§10.4）。
- `msg` 不支持属性（§7.7），因此没有"异步 msg"；需要异步注解时用 `evt` + `note="…"`。
- 亚周期精确位置（"第 3.2ns 发生"）不在 v1.0 范围内，见 §12.4。

## 7. 事件类型

所有类型的共同约定：

- 名字字段（`<名字>`、`<轨>`）区分大小写，**应当** 使用点分层级路径（`core.if.pc`），以便可视化按前缀分组。
- 名字 **必须** 非空。
- 参数个数必须与类型定义相符：缺必需字段 ⇒ 非法记录；多出的参数 ⇒ 非法记录。
- **追踪键**：`cnt`/`val`/`fsm`/`evt` 的追踪键是 `(域, 名字)` 每条记录都属于它自己 `dom=` 指定的那个域，同名但域不同的追踪对象彼此独立（两条轨迹），可视化 **应当** 分层显示；**没有** "某个名字首次出现即绑定到某个域" 的规则。`pip` 的追踪键只有**轨道名**（见 §7.4），因为跨时钟域轨道的记录天然落在不同域里。`msg` 没有追踪键。
- **名字集合必须有界**：名字是插桩**设计时**固定的标识（模块/信号/轨道/状态机名），**不得** 按条目、请求、指令、事务等**运行时对象**动态拼名（例如 `[fsm] "core.mshr[M2]", WAIT`、`[val] "core.rob[17]", …`）。否则追踪对象数会随仿真时间增长，违反 §13.2 第 10 条的有界内存承诺。需要表达"某个条目的状态/里程碑"时，**应当** 用 `pip` 的值带上稳定 ID（并在将来用 `ref=` 关联，见 §12.4）。

### 7.1 `clk` 时钟沿

```ebnf
clk = "clk" , <边沿> , [ dom = <时钟域> ] ;
<边沿> ∈ { "p" , "n" }
```

| 参数 | 类型 | 必需 | 说明 |
| --- | --- | --- | --- |
| 1 | `sym` | 是 | 沿：`p`（上升沿）或 `n`（下降沿） |

- 域 **必须** 由 `dom=` 属性指定，缺省为 `default` 与其它所有记录类型完全一致；`clk` 不存在"参数个数决定语义"的特例。
- 沿只有 `p`/`n` 两种拼写，大小写敏感；其它取值 ⇒ 非法记录（§10.3）。

```chiperf
[clk] p
[clk] n
[clk] p, dom=core
[clk] n, dom="mem"
```

### 7.2 `cnt` 计数器

```ebnf
cnt = "cnt" , <名字> , [ <增量> ] ;
<增量> = int ;
```

| 参数 | 类型 | 必需 | 说明 |
| --- | --- | --- | --- |
| 1 | 名字 | 是 | 计数器名 |
| 2 | `int` | 否 | 增量，缺省 `+1`；**可以** 为负 |

类型专属属性：

| 属性 | 值类型 | 说明 |
| --- | --- | --- |
| `abs` | `int` | 绝对值设置：把累计值直接置为该整数 |

- 语义：`total(name) += delta`。默认 `+1`，因此 `[cnt] "Branch Miss"` 表示"又发生了一次"。
- `abs=` 用于硬件计数器回读（溢出重载、清零后重捕）或复位：`[cnt] "Retired", abs=0`。
- 增量与 `abs=` **不得** 同时出现（该记录非法）。
- 增量 **必须** 是 `int`（不得是 `real`/`str`/`x`/`z`）；否则该记录非法。
- 计数器的**每一次** `cnt` 记录都是一个事件，其位置（时钟沿）被完整保留 —— 可视化由此得到"次数 + 发生沿"两个维度。
- `total` 变为负数 **不得** 判为非法；产生 `negative_total` 诊断。

```chiperf
[cnt] "Branch Miss"
[cnt] "Branch Miss", 3
[cnt] "Retired", -1
[cnt] "L2 Access", 1, dom="core"
[cnt] "Retired", abs=1234567
```

### 7.3 `val` 数值采样

```ebnf
val = "val" , <名字> , <值> ;
```

| 参数 | 类型 | 必需 | 说明 |
| --- | --- | --- | --- |
| 1 | 名字 | 是 | 数值名（信号/表达式） |
| 2 | 任意标量 | 是 | 采样值 |

- 语义：**保持型**。收到采样后，该名字的值一直保持到下一次采样。
- 首个采样之前的状态为 `unknown`（4 态 `x`），可视化 **应当** 渲染为未知区段。
- 一条记录只描述一个标量。多个信号 **必须** 写成多条记录。
- 值类型随字面量：`int` / `bits`（含 `x`/`z`）/ `real` / `str` / `sym`。字符串值适合记录"正在执行的指令"这类不可数值化的内容。
- 宽度信息若来自 Verilog 字面量（`32'h...`），解析器 **应当** 保留；否则宽度未指定。

```chiperf
[val] "PC", 0x800001d0
[val] "core.if.pc", 32'h8000_01d0
[val] "ID.instr", "addi a0,a0,1"
[val] "ctrl.state", IDLE
[val] "L1D.tag_valid", 4'b10xz
[val] "vdd", 0.95
```

### 7.4 `pip` 在飞条目（流水级 / 缓冲 / 通道）

```ebnf
pip = "pip" , <轨> , ( <值> | "bubble" ) ;
```

| 参数 | 类型 | 必需 | 说明 |
| --- | --- | --- | --- |
| 1 | 轨道名 | 是 | **应当** 用层级路径，如 `core.if`、`core.mem.lsq` |
| 2 | 任意标量 / `bubble` | 是 | 该级**此刻变成**的取值；`bubble` 是保留裸词，表示该级变空 |

语义：**保持型**，与 `val`（§7.3）同构 —— 每条 `[pip]` 直接指定该级的新取值，
**没有 `[pip]` 记录的那一拍保持上一值**。

| 记录 | 该级此后的内容 |
| --- | --- |
| `[pip] "core.if", 0x1234abcd` | 持有 `0x1234abcd`：一个**在飞条目**从这一拍开始 |
| `[pip] "core.if", x` | 持有未知值：在飞，但内容未知（小写裸词 `x` 是 4 态标量，§4.5） |
| `[pip] "core.if", bubble` | 空：该级没有内容（气泡从这一拍开始） |
| （没有记录） | 保持上一值不变 |

由此得到四件**不需要额外语法**的事：

- **条目的结束**：把该级设成别的值（或 `bubble`）的那条记录就是它的结束位置；
  不存在（也不需要）显式的"出队"记录。
- **同一个值再写一次是空操作**：该级一直持有它，那条记录只是在说"还是它"。
  因此 **没有**"标记唯一性"约束 —— 重复标记只表示"还是同一条内容"。
- **首条记录之前**该级处于**未开始**状态：既不是条目也不是气泡（与 `val` 的 `unknown` 同理）。
- **一个轨道同时只有一个当前值**：需要"多个条目同时在飞"（队列/多入口缓冲）时，
  用多条轨道分别表达（轨道名在设计期固定，§5.4）。

同值判据（决定"值有没有变"）与 §9.3 的**变化**口径一致：按值类型比较（`valueKey`）——
`32'h1` 与 `1` 不是同一个值，`8'h2a` 与 `8'h2A` 是同一个值。

```chiperf
[pip] "core.if", 0x1234abcd      # 0x1234abcd 进了 IF（条目开始）
[pip] "core.id", 0x1234abcd      # 它到了 ID；IF 那一条保持不动，直到 IF 被设成别的值
[pip] "core.if", 0x5678ef01      # IF 换成下一条：0x1234abcd 在 IF 里的区间到此为止
[pip] "core.id", bubble          # ID 变空：0x1234abcd 在 ID 里的区间到此为止（此后它不在流水里）
```

其它约定：

- 第 2 参数上 `bubble` 是保留裸词；`I` / `O` / `X` 三个词同样保留（它们是早期草案的方向，
  见 §12.1），写在这个位置会被判为非法记录并给出迁移提示（§10.4.1）。
- 轨道键 **只有轨道名**（不含域）：同名即同一级。跨时钟域轨道的记录天然落在不同域里，
  轨道绑定到它**第一条记录**所在的域；后续记录落在别的域时，条目的周期驻留按 §9.4 处理。
- 文件结束时**仍持有**的条目 **必须** 作为 `open`（未闭合）条目暴露，**不得** 臆造结束位置（§10.5）。

### 7.5 `fsm` 状态机

```ebnf
fsm = "fsm" , <名字> , <状态> ;
```

| 参数 | 类型 | 必需 | 说明 |
| --- | --- | --- | --- |
| 1 | 名字 | 是 | 状态机名，如 `core.ctrl` |
| 2 | `sym`/`str`/`int` | 是 | 当前状态 |

- 语义：**保持型**，与 `val` 相同。首个记录之前状态为 `unknown`。
- 连续两条 `fsm` 记录构成一次跳转 `from → to`；`from == to` 时是**自环**（合法，产生 `self_transition` 记录，可视化 **可以** 合并显示）。
- `fsm` 与 `val` 携带同一个名字时 **应当** 避免（前者是状态轨，后者是数值轨，追踪键相同但语义类型不同，可视化无法判定该画哪一种）；解析器 **必须** 接受该情况并产生 `name_reused` 诊断，**不得** 判为非法。

```chiperf
[fsm] "core.ctrl", IDLE
[fsm] "core.ctrl", FETCH
[fsm] "core.ctrl", FETCH      # 自环：状态未变但被再次断言
```

### 7.6 `evt` 瞬时事件

```ebnf
evt = "evt" , <名字> , [ <载荷> ] ;
```

| 参数 | 类型 | 必需 | 说明 |
| --- | --- | --- | --- |
| 1 | 名字 | 是 | 事件名 |
| 2 | 任意标量 | 否 | 载荷（如中断号、请求 ID） |

- 语义：瞬时发生、不保持、不累加。与 `cnt` 的区别在于**意图**：
  - `cnt` 表示"这是一个计数器"，可视化给累计值与速率；
  - `evt` 表示"这是一次离散标记"，可视化给事件点/载荷分布。
- `evt` 与 `cnt` 使用同名 **应当** 避免（一个是离散标记，一个是累加器）；解析器 **必须** 产生 `name_reused` 诊断。

```chiperf
[evt] "reset released"
[evt] "irq", 3
[evt] "tlb.way", 2, note="demand miss"
```

### 7.7 `msg` 自由文本

```ebnf
msg = "msg" , <文本> ;
```

- `<文本>` = 从 `msg` 之后到行尾的全部内容，去掉首尾空白；**不** 解析逗号、属性与 `#` 注释。
- 实现提示：`msg` 的载荷 **必须** 在剥除行尾注释之前取出；其它类型相反（先剥注释再解析字段）。顺序弄反会把文本里的 `#` 当成注释截断。
- 若该文本整体恰好是一个合法字符串字面量（`"..."`），解析器 **必须** 剥除引号并解码转义。
- `msg` 不携带语义，可视化 **应当** 在日志泳道显示。
- `msg` **不支持任何属性**（`dom=`、`at=`、`async=`、`note=` 都会被当成正文的一部分）。需要带定位/标记的注解时用 `evt` + `note="…"`（例如 `[evt] "irq.serviced", note="…", async=1`）。
- 用途：给人类看的注解（仿真开始/结束、模式切换、已知异常）。

```chiperf
[msg] reset released, starting trace
[msg] "entering turbo mode"
```

### 7.8 `rst` 系统复位

```ebnf
rst = "rst" ;
```

**语义：丢弃此前的一切事件记录。** `[rst]` 是一个**控制记录**，不是事件：

| 方面 | 规定 |
| --- | --- |
| 被丢弃的内容 | 本行之前**全部已被接受的事件记录**（`clk`/`cnt`/`val`/`pip`/`fsm`/`evt`/`msg`）及其派生量：在飞条目、计数器累计、数值保持值、状态机状态、事件轨、延迟与占用度统计 |
| 不受影响的内容 | 版本行与 `@` 指令（`@meta`、`@domain` 的 `period`/`freq`/`note`…）—— 它们是**声明**不是行；域集合与周期换算继续有效 |
| 周期号 | **不重编**：`cycles` 继续累加，复位后记录的周期号接着原来的数往下排（复位不会让时钟"回到 0"）；域上的"记录范围"（`first_cycle`/`last_cycle`）与"上升沿数/下降沿数"按**复位后的窗口**重算 |
| 位置与序号 | `rst` 不占位置、不占 `seq`、不产生记录 —— **不进任何可视化**（没有泳道、没有标记、没有表格行） |
| 诊断 | 复位会把此前窗口的诊断与跳过行一并作废（它们描述的是已被丢弃的数据），并产生一条信息性诊断 `rst_boundary`（"丢弃了 N 条"） |
| 参数 | **不允许**任何参数或属性（`dom=`/`at=`/`async=` 都算非法记录） |

复位是"当作没发生过"，不是"画一条竖线"：工具里看到的时间轴就是从复位处开始的那一段。

**复位处正在飞的条目**随复位一并销毁：复位之后该级处于"未开始"状态（§7.4），直到下一条 `[pip]` 把它设成某个值或 `bubble`。因此复位后紧接着写 `[pip] "core.if", bubble` 也完全正常 —— 那只是"该级变空"，不是错误。

```chiperf
chiperf 1.1
@domain default, period=1.0ns
[clk] p
[cnt] "retired"
[clk] n
[rst]                       # 之前的记录整批作废（上面的 retired 不再计入）
[clk] p
[cnt] "retired"             # 复位后第一个周期：累计从这里重新开始
[clk] n
@end
```

**版本**：文件 **应当** 在版本行声明 `chiperf 1.0`（§5.4）。不认识 `rst` 的工具会把它当未知记录类型忽略（§10.2 的 `skipped_unknown_kind`），于是显示复位前的数据 —— 这是给格式追加记录类型的固有代价，取舍见 §12。

## 8. 指令

指令以 `@` 开头，描述文件自身。语法：`@ <名字> [参数...] [属性...]`。

- 未知指令 **必须** 被忽略（`unknown_directive` 诊断）。
- 指令不占用 `seq`，不产生事件，不改变任何域的时钟状态。

### 8.1 `@meta` 元数据

```chiperf
@meta design="rv32i-core" tool="verilator-5.028" date="2026-09-15" argv="-DTURBO"
@meta simulator="VCS"
```

- 全部字段都是 `键=值` 属性；键任意，重复键最后一条生效。
- 解析器 **必须** 以字符串/原值形式保留，供可视化做标题、分组、过滤。
- 不同 `@meta` 行 **可以** 多次出现，累积合并。

### 8.2 `@domain` 声明时钟域

```chiperf
@domain core
@domain "core", period=1.0ns, note="主时钟"
@domain mem, freq=800MHz
```

| 参数 | 类型 | 必需 | 说明 |
| --- | --- | --- | --- |
| 1 | 域名 | 是 | 参数 |
| `period` | 缩放量（时间） | 否 | 上升沿间隔 |
| `freq` | 缩放量（频率） | 否 | 频率；与 `period` 同时给出时以 `period` 为准 |
| `note` | 字符串 | 否 | 注释 |

- 时间换算：若给出 `period`，域内第 `k` 个上升沿的时刻为 `(k-1) × period`（第一个上升沿位于 0）；若只给出 `freq`，则 `period = 1/freq` 后再按同式换算。可视化 **可以** 用它将周期轴换算为时间轴。
- 对同一域重复声明 **必须** 被接受，属性逐项合并（后者覆盖前者），并产生 `duplicate_domain` 诊断。
- `@domain` 声明本身 **不得** 建立域的时间基准：`cycles`/`phase` 仍由 `[clk]` 记录推进。

### 8.3 `@end` 正常结束标记

```chiperf
@end
```

- 语义：写入者已完成全部记录，文件**不是**被截断的。
- `@end` **必须** 是最后一条非注释记录；若其后仍有记录，解析器 **必须** 解析它们并产生 `records_after_end` 诊断。
- 缺失 `@end` ⇒ `eof_without_end_marker` 诊断（文件可能被截断）。

## 9. 派生量

解析器的输出分两层：

- **核心层（MUST）**：记录序列 + 每条记录的位置 + 值的类型化表示 + `async` 标志（§6.7）+ 诊断计数。
- **派生层（SHOULD）**：下列量。它们的定义是规范性的，以保证不同可视化工具算出的数字一致。

约定：

- 派生量是**函数**，不是必须物化的表。长轨迹下逐周期物化 `inflight`/`state_at` 会产生 1e10 量级的项，实现 **可以** 按需计算，或用稀疏/直方图/分段常量表示，只要取值与定义一致。
- 所有派生量都以**位置**（域 + 周期）为输入；跨域比较见 §6.5。

### 9.1 时钟

| 派生量 | 定义 |
| --- | --- |
| 上升沿数 | 域内 `p` 记录数 = `cycles[d]` 终值 |
| 下降沿数 | 域内 `n` 记录数 |
| 边沿序列 | 域内全部 `clk` 记录的位置，按 `seq` 排序 |
| 周期频率 | 若有 `period`：`1/period` |

若某域只写了 `p`，其相位恒为 `p`，周期编号仍然完整可用（AGENT.md 示例即是这种写法）。

### 9.2 计数器（`cnt`）

| 派生量 | 定义 |
| --- | --- |
| 事件位置序列 | 每条 `cnt` 记录的位置（回答"发生时的对应时钟沿"） |
| 总量 | `total(name, t) = Σ delta`；出现 `abs=` 的记录把总量直接置为该值 |
| 每周期增量 | `delta(name, c) = Σ { delta : cycle = c }` |
| 速率 | `delta(name, c) / period`（若有 `period`） |
| 区间差 | `delta_between(name, c1, c2) = total(name, c2) − total(name, c1)` 针对周期性 `abs=` 回读的采样轨迹（§6.6） |
| 区间速率 | `delta_between(name, c1, c2) / (c2 − c1)` |

带 `abs=` 的记录 **只置总量，不贡献 `delta`**（它不代表"发生了 N 次"，而代表"计数器此刻读到 N"）；因此"该周期的计数增量"要用前后两次 `total` 相减得到。

采样轨迹上的比率（命中率、IPC 之类）**应当** 由两条区间差相除得到，而**不是** 另写一条 `val` 记录：一个概念只应有一种写法（§1.1）。

### 9.3 数值（`val`）

| 派生量 | 定义 |
| --- | --- |
| 采样序列 | 每条 `val` 记录的位置与值 |
| 某时刻状态 | `state_at(name, c)` = 在满足 `cycle ≤ c` 的全部采样中，按 `(cycle, 相位序, seq)` 取最大者的值（相位序 `p < n`）；不存在则 `unknown` |
| 变化事件 | 相邻两次采样值不同（按值类型比较；`x`/`z` 位参与比较）的位置对 |

- 未知 → 已知、已知 → 未知 **都算变化**。
- 值类型不同（`sym` 与 `int`）比较时 **必须** 按类型分别比较，不得强行数值化。

### 9.4 在飞条目（`pip`）

对每条轨道、每个条目（= 该级连续持有同一个值的那一段）：

| 派生量 | 定义 |
| --- | --- |
| `enter` | 把该级设成此值的那条记录的位置 |
| `close` | 把它改成别的值（或 `bubble`）的那条记录的位置；缺失 ⇒ `open`（§10.5） |
| `value` | 该条目持有的值 |
| `latency_cycles` | `close_cycle - enter_cycle`（同域）；跨域 **不得** 给周期差，改为给 `latency_time` 或两端位置 |
| `latency_time` | 跨域条目：`(c_close − 1) × period_close − (c_enter − 1) × period_enter`，仅当两端域都声明了 `period`（§8.2）时给出；相位不同时标注亚周期不确定性（± 半个源周期） |

对每条轨道、每个周期：

| 派生量 | 定义 |
| --- | --- |
| `inflight(track, c)` | `#{ item : enter_cycle ≤ c 且 (close_cycle 缺失 或 close_cycle > c) }`（半开区间）；跨域条目按 `enter` 域计。保持型语义下取值只有 0 或 1 |
| `arrivals(track, c)` | 周期 `c` 内把该级设成**某个值**（非 `bubble`）的记录数 |
| `departures(track, c)` | 周期 `c` 内**结束掉一个条目**的记录数（即"把该级从条目改成别的值"的那条） |
| `bubble(track, c)` | `inflight(track, c) == 0` 且 `track_first_cycle ≤ c ≤ track_last_cycle`（即该轨道首条记录所在周期 ~ 末条记录所在周期之间） |

约定与边界：

- **同一拍设值又改掉**的条目延迟为 0 周期，且不计入任何周期的占用度（半开区间 `[enter, close)`）。
- `close_cycle - enter_cycle` 的单位是"周期"，即上升沿个数之差。需要亚周期精度时用两端 `phase`。
- **跨域条目**的占用度按 `enter` 域统计（不重复计入 `close` 域）：其**结束时刻**取"结束记录被解析时
  `enter` 域的当前周期"（结束记录自己的周期属于另一条时间轴，不能直接拿来用）。
  端到端时间用 `latency_time`（两域都有 `period` 时）或只报两端位置。
- `track_first_cycle` / `track_last_cycle` 指该轨道**首条、末条记录**所在周期的周期号；跨域轨道同样按绑定域计。
- 统计可给出：驻留直方图、最小/最大/平均驻留、吞吐（`departures/周期`）、占用度时序、气泡段长分布。
- **不复存在**：完成/撤销（`O`/`X`）之分、"凭空出队"、"重复标记"。冲刷/取消在 v1.0 里就是
  "该级被设成 `bubble`" —— 与"正常离开"在数据上不可区分（这是保留型模型的取舍，见 §12.5）。

### 9.5 状态机（`fsm`）

| 派生量 | 定义 |
| --- | --- |
| 状态时序 | 同 `val` 的 `state_at` 定义（保持型） |
| 跳转表 | 相邻两条 `fsm` 记录构成的 `(from, to)` 对，含位置 |
| 自环 | `from == to` 的跳转，单独计数 |
| 驻留 | 同域相邻两条记录之间的周期差；**最后一个状态的驻留不可确定**（还没有下一条记录），可视化应当把它画成开放区间而不是 0 |

### 9.6 可视化泳道（建议模型）

规范不约束布局，但下列"泳道 → 记录类型"映射被建议采用，以保证工具间观感一致：

| 泳道 | 数据源 | 呈现 |
| --- | --- | --- |
| 时钟 | `clk` | 方波 + 周期标尺；域内只写了 `p` 时下降沿按周期中点补出（见下） |
| 异步事件 | 任意带 `async=1` 的记录 | 画在所在区间的**内部**（两个沿之间），不与沿刻度对齐；建议空心/虚线样式 |
| 计数器 | `cnt` | 累计值曲线 + 每周期柱状增量 + 事件点 |
| 数值 | `val` | 阶梯波形（未知为阴影） |

只写了 `p` 的域（§6.2 第 3 条允许的省事写法）在文件里没有 `n` 记录，但 §6.1 第 5 条已把每个周期定义为"先 `p` 段（高）再 `n` 段（低）"，下降沿的位置因此是确定的（周期中点）。可视化 **应当** 据此把方波画完整，否则波形会停在第一次上升沿之后的高电平。这是**渲染推断**：**不得** 写回数据，也 **不得** 改变 §9.1 的"下降沿数"（那仍然是域内 `n` 记录数）。
| 在飞轨道 | `pip` | Gantt：每个条目从 `enter` 画到 `close`；`open` 用虚线；该级为空的那几拍画成气泡 |
| 占用度 | `pip` 派生 | `inflight` 柱状；0 为气泡 |
| 状态机 | `fsm` | 状态色带 + 跳转图 |
| 事件 | `evt` | 事件点/标记，可带载荷标签 |
| 文本 | `msg` | 日志行 |

## 10. 鲁棒性与恢复

鲁棒性是本格式的第一设计约束：仿真器随时可能被杀掉，插桩也可能写错。

### 10.1 前缀封闭性（核心性质）

> **P1**：若 `F` 是合法 chiperf 文件，`F'` 是 `F` 的一个以行终止符结尾的前缀，则 `F'` 也是合法 chiperf 文件。

理由：记录不跨行、记录自包含、所有跨记录状态（计数总量、数值保持、在飞条目、FSM 当前态）都是**派生**而非**声明**。`F'` 在语义上可能缺少后续事件、可能留下未闭合的 `pip` 条目 —— 但语法与位置模型完全有效。

由此得到的解析器义务：

- **MUST** 丢弃末尾**未以行终止符结束**的那一行（它可能是被写一半的残行），并 **SHOULD** 通过 `truncated_tail` 诊断把该行原文暴露出来。
- **MUST NOT** 因为文件不完整而拒绝解析或抛出致命错误。

### 10.2 未知记录类型

- 未知的 `[kind]` ⇒ **必须** 跳过该行并继续，计数 `skipped_unknown_kind`。
- 解析器 **SHOULD** 保留原始行文本（`unknown_records`），供工具做前瞻兼容。
- 未知的 `@directive` ⇒ **必须** 跳过，计数 `skipped_unknown_directive`。
- 未知的属性键 ⇒ **必须** 忽略，不影响该记录其余字段的解析。

### 10.3 非法记录

以下情况判为"非法记录"：**必须** 跳过该行、计数 `skipped_invalid_record`、继续解析下一行。

- `clk` 的沿取值不在允许集合内；
- `[pip]` 缺少第 2 个参数（值或 `bubble`）；或该位置写成了保留词 `I`/`O`/`X`（早期草案的方向，§7.4）；
- 行首不是 `[`、`@`、`#` 的行（含出现在首行之外的版本行，见 §5.4）；
- 必需参数缺失，或参数个数过多；
- 参数出现在属性之后；
- 字符串未闭合；
- `cnt` 的增量不是 `int`，或增量与 `abs=` 同时出现，或 `abs=` 的值不是 `int`；
- `at` 属性值不符合 `int[p|n]`，或 `async` 的值不是 `0`/`1`；
- 缩放量出现在非 `@domain.period/freq` 位置；
- 参数为空（如 `[cnt] "x",`）。

解析器 **SHOULD** 在诊断里带上行号与该行原文。**MUST NOT** 因为一行非法而放弃文件中任何其它记录。

### 10.4 语义异常（不判非法）

以下情况合法，但 **MUST** 被记录为诊断：

| 诊断 | 触发 |
| --- | --- |
| `undeclared_domain` | 文件里存在 `@domain` 声明，而某个域名被记录使用却未声明（拼写错误会静默新建一条时间轴）；按**域名**去重计数，`default` 不受此约束 |
| `at_clk_conflict` | 同一域内同时使用了 `clk` 记录与 `at=` 定位（两者混用会让"位置"与"周期计数"脱节） |
| `async_on_clk` | `clk` 记录上出现 `async=1`（时钟沿本身不可能异步；该属性被忽略） |
| `negative_total` | 计数累计值变负 |
| `self_transition` | `fsm` 相邻两条同状态 |
| `redundant_edge` | 同相位重复的 `clk` |
| `rst_boundary` | `[rst]` 复位：此前的记录已被丢弃（信息性，说明窗口为什么从这里开始） |
| `duplicate_attribute` | 同名属性重复 |
| `duplicate_domain` | 同域重复声明 |
| `name_reused` | 同一名字被不同类型（`cnt`/`val`/`fsm`/`evt`）使用 |
| `records_after_end` | `@end` 之后仍有记录 |
| `cross_domain` | `pip` 条目的起始记录与结束记录落在不同域 |
| `eof_without_end_marker` | 文件以无 `@end` 的 EOF 结束 |

### 10.4.1 容器层与词法层的诊断

上面那张表列的是**语义异常**（数据合法、只是可疑）。另有一组诊断来自数据完整性本身，单独列出，避免与语义异常混为一谈：

| 诊断 | 触发 | 出处 |
| --- | --- | --- |
| `truncated_tail` | 末尾未以行终止符结束的行被丢弃（原文一并报告） | §10.1 |
| `skipped_unknown_kind` / `skipped_unknown_directive` / `skipped_invalid_record` | 被跳过的行（§10.2 / §10.3） | §10.2 / §10.3 |
| `invalid_escape` | 字符串里的未知转义按字面字面容错 | §4.2 |
| `pip_legacy_direction` | `[pip]` 的第 2 参数写成了早期草案的方向 `I`/`O`/`X`（该行同时计一次 `skipped_invalid_record`）；给迁移用的显式计数 | §7.4 |
| `gzip_truncated` | gzip 流被截断（已解出的记录仍然保留） | §10.6 |
| `gzip_checksum_mismatch` | gzip 成员的 CRC32/ISIZE 校验失败（数据仍然交付） | §10.6 |
| `gzip_bad_format` | 魔数正确但 gzip 头部/流结构损坏 | §10.6 |

### 10.5 未闭合条目

- 文件结束时**仍在持有**某个值的 `pip` 条目（此后没有任何记录把它改掉）：**MUST** 作为 `open` 条目暴露（含 `enter` 位置与 `value`），**MUST NOT** 伪造 `close`。
- 可视化 **SHOULD** 把 `open` 条目渲染为虚线/开放区间，让"仿真在这里被切断"一眼可见。

### 10.6 gzip 的部分恢复

- 解析器 **MUST** 使用流式解压（inflate），边解压边解析，**不得** 要求先完整解压到内存后再校验 CRC。
- gzip 流的尾部截断（`unexpected end of file`）时：**MUST** 保留截断点之前已解压出的完整行并正常解析；**MUST** 产生 `gzip_truncated` 诊断。
- CRC32/ISIZE 校验失败：**MAY** 忽略该失败以完成恢复解析，但 **SHOULD** 产生 `gzip_checksum_mismatch` 诊断。
- 写入者 **SHOULD** 在 gzip 模式下使用 `Z_SYNC_FLUSH`（或等价的分块 flush），使崩溃时已写出的数据可被解出。

### 10.7 解析器必须报告的东西

一个符合规范的解析器 **MUST** 能报告：

1. 版本（显式或隐含的 `1.0`）；
2. 全部域名与各自周期/边沿数；
3. **可流式地**报告全部事件及其位置（逐条产出即可；**不得** 要求先把全部事件物化到内存 —— 见 §13.2 第 10 条）；
4. §10.4 的全部诊断与计数；
5. `open` 条目清单；
6. `truncated_tail` 的原始文本（若存在）。

## 11. 写入者指南

- **W1** 每条记录 **必须** 以 `\n` 结尾；写完 **应当** 立即 flush 或使用行缓冲。这是鲁棒性的前提（§10.1）。
- **W2** gzip 模式下 **应当** 定期 `Z_SYNC_FLUSH`。
- **W3** 每个时钟沿 **必须** 先写 `[clk]`，再写该沿发生的全部事件；记录 **必须** 满足"**每域**位置非递减"（§6.3，跨域顺序不作要求）。
- **W4** **不得** 让一条记录跨行；字符串内 **不得** 出现裸换行。
- **W5** 名字 **应当** 采用稳定的层级路径（`<模块路径>.<信号>`），且在一次仿真内保持不变 —— 可视化依赖名字分组。
- **W6** 正常结束时 **必须** 写 `@end`（让工具区分"完成"与"被切断"）。
- **W7** 文件首行 **必须** 写版本行；**应当** 再写 `@meta`（`design`/`tool`/`date`），便于归档与复现。
- **W8** 需要跨周期追踪的内容 **应当** 在 `pip` 的值里带上稳定 ID（PC、请求号）：同一个值在多级之间出现即表示"同一条内容"，可视化据此跟色。
- **W9** 除后处理场景外，**不得** 用 `at=` 打乱位置顺序。
- **W10** 插桩 **必须** 保证"每个沿都写 `[clk]`"，只有上升沿也足够；但 **不得** 在同一个域里同时使用"只写 `p`"和"同时写 `p`/`n`"两种模式。
- **W11** 不是在该记录的时钟沿上采样到的事件（外部中断、DMA 完成、异步握手回报、中途采样的计数器…）**应当** 标 `async=1`，否则可视化会把它吸附到沿刻度上，读者会误以为它发生在沿上；反过来，确实在沿上采样的事件 **不得** 标 `async`。
- **W12** 把该级改成别的值（或 `bubble`）的那条记录 **应当** 写在"内容确实占用过的那一周期**之后**"的那一拍：条目占据 `[enter, close)`，把 `close` 写成最后占用周期的**当拍**会让区间变成 `[c, c)`（零宽），该条目随之不计入任何周期的占用度（§9.4）—— 图上看不见、占用度曲线上也没有它。同一拍设值又改掉只用于确实不占周期的组合直通（§9.4）。

## 12. 版本与扩展

### 12.1 版本号

- 格式为 `chiperf <major>.<minor>`。
- 次版本 `+1` ⇒ 仅**新增**记录类型/属性/指令（向后兼容）：旧解析器 **必须** 跳过未知内容而非报错（§10.2）。
- 主版本 `+1` ⇒ 有语义变更或字段重定义（不兼容）：解析器 **必须** 默认拒绝该文件。

### 12.2 扩展的三条安全路径

新增能力时，按优先级选择：

1. 新增属性键（旧解析器忽略，代价最低）；
2. 新增记录类型（旧解析器跳过，数据不丢文件、只丢该类型语义）；
3. 新增指令（描述文件自身，不影响事件流）。

### 12.3 厂商扩展

- 厂商私有属性键 **应当** 使用 `x-` 前缀（如 `x-vendor-retry=3`），以避开未来标准键名。
- 厂商私有记录类型 **应当** 使用 `x-` 前缀（如 `[x-vendor-bp]`）。

### 12.4 保留字

以下类型名与属性键为未来标准预留，厂商 **不得** 占用：
`stall`、`dep`、`lat`、`bw`、`power`、`perf`、`begin`、`end`（类型名）；`id`、`ref`、`parent`、`unit`、`width`（属性键）。

候选方向（本文档不定义，仅备忘；括号内是缺口所在，来自对真实微架构场景的探针分析）：

| 方向 | 缺口 | 归属 |
| --- | --- | --- |
| 符号/字典压缩（`@sym`） | 名字内联占大轨迹的多数字节 | 体积与吞吐的最大杠杆 |
| 条目引用 `ref=`/`parent=` | 条目的**中间里程碑**（ROB 的 complete、MSHR 的 merge、总线的 grant）与**同一逻辑操作的多次占用**（重试、4KB 拆分）无法关联到条目 | 属性（已预留键名） |
| 容量与并行组 `@track depth=` / `@group width=` | 只有绝对占用度，算不出利用率；并行端口组不可声明 | 指令 |
| 分类原因 `reason=` | 结束原因（正常离开、端口冲突、冲刷、取消）在保持型模型里**不可区分**（§9.4），只能塞进 `note=`，机器不可读 | 属性 |
| 数值单位 `unit=` | 比率类数值（IPC、命中率）无法机器可读地标注 | 属性（已预留键名） |
| 区间/测量段 `begin`/`end`、窗口统计 | 没有区间原语，窗口内的周期数/stall 分布只能在规范外统计 | 类型 |
| 依赖边 `dep`、停顿建模 `stall` | 因果关系（谁在等谁、为什么停）不可表达（§1 的非目标） | 类型 |
| 亚周期精确位置 `frac=`（0~1 的区间内相位） | `async=1` 只说明"在区间内部"，不说明具体偏移；需要精确到 ns 时必须落回两条沿之间 | 属性 |
| 多值行 | 一条采样 = N 行，截断后可能半组 | 语法 |

其中 **符号/字典压缩** 是最有价值的解析器侧改进：大轨迹里重复写出的名字占了多数字节，一次 `@sym` 定义 + 短标识引用可显著减少 I/O 与字符串驻留开销。其设计约束是 **定义必须先于使用**，这样 §10.1 的前缀封闭性依然成立（前缀最多丢失尾部引用，逐行跳过即可）。

`ref=` 若引入，**必须** 遵守同一条"先引用后出现"约束（只能引用已经出现过的条目），否则解析器要么无法解析，要么必须缓存全部历史条目，破坏 §13.2 第 10 条的有界内存承诺。

## 13. 一致性

### 13.1 写入者（Writer）

满足以下全部条件即为"chiperf 1.0 兼容写入者"：

1. 输出 UTF-8、LF 结尾、每条记录一行、每行以 `\n` 结束（W1）。
2. 首行写出版本行 `chiperf 1.0`（W7）。
3. 只使用 §7 定义的 7 种类型与 §8 定义的指令；名字非空；字段数与类型正确。
4. 字符串转义仅用 §4.2 的 5 种；不在字符串中写裸换行。
5. 时钟沿用 `clk` 记录表达，且每个域的时间推进只依赖 `p` 记录；一个域内只用一种边沿插桩模式。
6. 满足"每域位置非递减"（§6.3）。
7. 正常结束时写 `@end`。
8. 非时钟沿采样的事件用 `async=1` 标注（W11）。

两类写入者都算合规，但**必须** 满足各自的附加条件：

- **时钟驱动写入者**：满足以上 1~7。
- **无时钟写入者**（采样器/后处理工具，§6.6）：每条记录的域 **必须** 由 `dom=` 显式给出（否则会落到 `default`），`at=` 的周期在域内非递减；第 5 条不适用。

### 13.2 解析器（Parser）

满足以下全部条件即为"chiperf 1.0 兼容解析器"：

1. 满足 §10.1 前缀封闭性（丢弃未终止的尾行、绝不因不完整而失败）。
2. 接受缺失版本行的文件（按 `1.0` 解释），拒绝未知主版本（§5.4）。
3. 未知类型/指令跳过并计数；未知属性忽略（**可以** 计数）（§10.2）。
4. 非法记录逐行跳过并计数，不影响其它记录（§10.3）。
5. 正确实现 §6 的位置模型（含 `at=` 覆盖、相位与周期编号、多域）。
6. 正确实现 §7.4 的保持语义（无记录则保持上一值、重复写同值不产生新条目、结束位置由下一条记录给出）。
7. 正确实现 §9 的派生量定义（核心层 MUST，派生层 SHOULD）。
8. 能报告 §10.7 的六项内容。
9. 支持 `.chiperf.gz` 的流式解析与部分恢复（§10.6）。
10. 对不含 `at=` 的文件，可以依赖**每域位置单调性**做单遍流式处理，内存占用只与"在飞条目数 + 追踪对象数"相关（§6.3；因此名字集合必须有界，§7）。
11. 在核心层暴露 `async` 标志；`clk` 上的 `async=1` 只产生诊断、不改变沿的语义（§6.7）。

## 附录 A：完整示例

AGENT.md 中给出的示例（此处补上写入者必须写出的版本行）在 v1.0 语法下如下：

```chiperf
chiperf 1.0
# 上升沿：一个周期开始
[clk] p
[cnt] "Branch Miss"
[cnt] "Cache Hit"
[val] "PC", 0x800001d0
[pip] "IF", 0x1234abcd          # IF 此刻持有 0x1234abcd
[pip] "IF", bubble              # 同一拍后半段：IF 变空（该级没有内容了）
# 下降沿：同一周期的后半段
[clk] n
# 下一个周期
[clk] p
```

派生结果：

| 记录 | 位置 |
| --- | --- |
| `[clk] p` | `(default, 1, p, 1)` |
| `[cnt] "Branch Miss"` | `(default, 1, p, 2)`，`total = 1` |
| `[cnt] "Cache Hit"` | `(default, 1, p, 3)`，`total = 1` |
| `[val] "PC"` | `(default, 1, p, 4)`，`PC = 0x800001d0` |
| `[pip] "IF", 0x1234abcd` | `(default, 1, p, 5)`，IF 开始持有 `0x1234abcd` |
| `[pip] "IF", bubble` | `(default, 1, p, 6)`，IF 变空 ⇒ 该条目驻留 = `1 - 1 = 0` 周期，第 1 周期占用度为 0 |
| `[clk] n` | `(default, 1, n, 7)` |
| `[clk] p` | `(default, 2, p, 8)` |

一份更完整的轨迹见 `docs/examples/`，逐条推导见 `docs/examples.md`。

## 附录 B：快速参考

```chiperf
chiperf 1.0                                     # 版本行（写入者必须写，且在首行）
@meta design="rv32i-core" tool="verilator"      # 元数据
@domain core, period=1.0ns                      # 声明时钟域
# 注释                                          # 行首或空白后的 '#' 到行尾
# 每域内行序按位置非递减（跨域不做比较）：解析器据此单遍流式输出

[clk] p                                         # default 域上升沿
[clk] n, dom=core                               # core 域下降沿
[cnt] "Branch Miss"                             # +1
[cnt] "Retired", 4                              # +4
[cnt] "Cycles", abs=1234567                     # 绝对值设置
[val] "PC", 32'h8000_01d0                       # 数值采样（保持）
[val] "instr", "addi a0,a0,1"                   # 字符串值
[val] "ok", 4'b10xz                             # 4 态（未知位/高阻位）
[pip] "core.if", 0x1234abcd                  # IF 此刻持有这条内容（条目开始；没记录就保持）
[pip] "core.id", 0x1234abcd                  # 它到了 ID（同一个值 ⇒ 可视化同色跟到下一级）
[pip] "core.if", bubble                         # IF 变空（没有内容；冲刷/取消也这么表达）
[pip] "core.mem", x                             # 有内容但内容未知（4 态标量）
[fsm] "core.ctrl", FETCH                        # 状态机
[evt] "irq", 3                                  # 瞬时事件（带载荷）
[evt] "irq.assert", 5, async=1                  # 异步事件：画在两个时钟沿之间，不对齐沿刻度
[cnt] "stall.sample", 1, async=1                # 区间内采到的计数（不在沿上）
[msg] reset released                            # 自由文本到行尾
[cnt] "Miss", dom="core", note="L1D"            # 通用属性
[val] "PC", 0x1000, at=42p                      # 显式位置覆盖
@end                                            # 正常结束
```
