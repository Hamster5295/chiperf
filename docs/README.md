# chiperf 文档

chiperf 是一种用于硬件微架构**性能分析与可视化**的通用文件格式：由 RTL 仿真期的插桩代码按"写文件"的方式逐行追加事件，之后由统一解析器解析、可视化。

设计原则是 **解析器优先**：文件的主要读者是工具链，不是人。

- 纯文本，后缀 `.chiperf`；gzip 容器，后缀 `.chiperf.gz`
- 事件驱动、一条记录一行、记录自包含 ⇒ 可单遍流式解析
- 崩溃安全：任意"按行切断"的前缀都是合法文件（前缀封闭）
- 一种概念只有一种写法；词法层没有特例；未知内容一律跳过而非报错
- 顺带的好处：纯文本、名字内联、`#` 注释，人类偶尔打开也能看懂大意

## 60 秒上手

```chiperf
chiperf 1.0
@meta design="rv32i-core"
@domain core, period=1.0ns

[clk] p, dom=core
[cnt] "Branch Miss"
[val] "core.if.pc", 32'h8000_01d0
[pip] "core.if", I, 0x800001d0
[fsm] "core.ctrl", FETCH
[clk] n, dom=core
[clk] p, dom=core
[pip] "core.if", O, 0x800001d0
@end
```

这一小段已经表达了：第 1 个上升沿分支预测失败一次、PC 的值、`core.if` 在这个周期开始处理 `0x800001d0`、控制器进入 `FETCH`；第 2 个上升沿该内容离开 `core.if`（延迟 1 周期）。

## 能力覆盖

AGENT.md 列出的追踪能力与记录类型的对应关系：

| 追踪能力 | 记录类型 | 关键点 |
| --- | --- | --- |
| 时钟上升沿/下降沿 | `clk` | 只有 `p` 记录也足以定义周期编号 |
| 事件次数 + 发生沿 | `cnt`（+ `evt`） | 每次增减都是一条带位置的记录 |
| 数值变化 + 发生沿 | `val` | 保持型采样，支持 4 态（`x`/`z`）与字符串 |
| 模块内正在处理的内容 | `pip` | 入/出事件配对，派生延迟与占用度 |
| 状态机变化 | `fsm` | 保持型；相邻记录构成跳转 |

## 解析器最小实现要点

1. 逐行读；丢弃末尾没有换行的残行（崩溃安全的前提）。
2. `[...]` 是事件，`@...` 是文件自身指令，`#` 到行尾是注释。
3. 认识 7 种事件：`clk` `cnt` `val` `pip` `fsm` `evt` `msg`；其余跳过并计数。
4. 位置 = `(域, 周期, 相位, 序号)`，由 `clk` 推进；`dom=` 选域，`at=` 显式覆盖（`at=` 不推进时钟）。
5. 永不因为一行坏掉而放弃整个文件；非法记录逐行跳过。
6. 语义异常（凭空出队、负计数、自环、重复标记、域拼写错误……）不改数据、只记诊断（§10.4）。
7. 单调性是**每域**的：跨域的周期号没有可比性（§6.3）。
8. `async=1` 表示"这条不是在时钟沿上采样的"：位置与派生量照旧，只是可视化要画在两个沿**之间**（§6.7）。
9. 派生量（延迟、占用度、状态时长……）都是**函数**，可以按需算，不必物化整表。

细节见 [`spec.md`](spec.md)；派生量（延迟、占用度、状态时长……）的精确定义见 spec §9。
