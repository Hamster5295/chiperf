# 设计取舍与演进

本文记录 `spec.md` 里每条硬规则**为什么是这样**，以及被否决的方案和已知代价。规范正文只写"是什么"，这里写"为什么"。

## 1. 优先级

用户给出的取舍顺序（本文按此执行）：

1. **可解析**：文件的主要读者是解析器与工具链，必须能单遍流式读、不依赖外部信息、不要求回读。
2. **鲁棒**：仿真随时可能被杀掉，或插桩本身写错；任何不完整/局部损坏的输入都要能解析出可用的部分。
3. **表达力**：能覆盖 RTL 性能分析关注的五类量（时钟、事件计数、数值、流水线在飞内容、状态机）。
4. **人类可读**：文本、名字内联、`#` 注释 —— 顺带的好处，**不是**设计指标。凡与 1~3 冲突时，牺牲它。

### 1.1 明确"解析器优先"后改掉的几处

草案早期是按"人类友好优先"写的，明确优先级后做了如下收紧（都是删特例、删选项，而不是加功能）：

| 改动 | 之前 | 之后 | 收益 |
| --- | --- | --- | --- |
| `clk` 的域 | `[clk] "core", p` 或 `[clk] p` | `[clk] p, dom=core` 或 `[clk] p` | 消灭"参数个数决定语义"，域处处走 `dom=` |
| 计数器绝对值 | `[cnt] "X", =1234` | `[cnt] "X", abs=1234` | 词法层不再有"以 `=` 开头的数值"特例 |
| 4 态裸词 | 仅值位置有效 | 任何位置有效 | 词法/语义规则不再依赖记录类型 |
| 写入顺序 | 应当非递减 | 必须非递减（`at=` 除外） | 解析器可单遍流式输出、不缓冲重排 |
| 版本行 | 可选 | 写入者必须写、解析器必须容忍缺失 | 新文件自描述，老文件仍可解析 |
| 沿的拼写 | `p`/`n`/`posedge`/`negedge` | 只有 `p`/`n` | 一种概念一种写法，解析器不做归一化 |
| 文档定位 | 强调"人类可读"为要求 | 明确人类可读只是辅助 | 后续取舍有据可依 |

## 2. 为什么是"文本 + 一条记录一行"

| 方案 | 单遍流式 | 崩溃安全 | 说明 |
| --- | --- | --- | --- |
| **chiperf（本方案）** | ✅ | ✅ 行边界前缀合法 | 一行一条独立记录 |
| 定长二进制记录 | ✅ | ⚠️ 尾部半条记录可跳过，但不可读、扩展要预留字段、大小端/位宽要定 | 需要版本化的行格式 |
| 位打包 / FST 风格 | ❌ | ❌ | 需要 Huffman/变长表，必须整块解压与回读 |
| 每行多条记录（CSV 一行一批） | ✅ | ⚠️ 截断会丢掉整批（多条的）记录 | 截断粒度变粗 |
| 单条 JSON（每行一个对象） | ✅ | ✅ | 体积 3~5×，需要 JSON 解析器与浮点/大整数坑 |
| VCD/FST 全量 dump | ✅ | ⚠️ | 体积 = 周期数 × 信号数，与"只记录发生的事"矛盾 |

关键性质是 **前缀封闭（§10.1）**：记录不跨行 + 记录自包含 + 所有跨记录状态都是派生量 ⇒ 任何以换行结束的前缀都是合法文件。这一条直接禁止了所有"与上一行做差分"的压缩手段：那类编码一旦丢行就会连锁失真。

## 3. 与既有格式的关系

| 维度 | chiperf | VCD | FST | JSONL |
| --- | --- | --- | --- | --- |
| 建模对象 | **语义事件**（计数、在飞条目、状态跳转） | 信号波形 | 信号波形 | 任意 |
| 体积 | 与"发生的事"成正比 | 与"周期数 × 信号数"成正比 | 小 | 大 |
| 仿真期写入成本 | 一行追加 + flush | 高（要维护全量时间表） | 中 | 中 |
| 截断后可用性 | 天然（前缀封闭） | 一般（时间表可能残缺） | 差（二进制容器） | 行式可用 |
| 延迟/占用度 | 解析器**原生**给出（§9.4） | 需要用户自己推导 | 同左 | 同左 |
| 解析器实现量 | 小（无递归、无符号表、无变长编码） | 中 | 大 | 中 |

chiperf 不打算取代波形数据库：需要看每一位信号随时间的变化时，应当去 dump VCD/FST；需要"每周期都在发生什么、谁卡住了、哪一级有多少气泡"时，chiperf 更省。

## 4. 逐条决定的理由

### 4.1 时间只由上升沿推进

- 周期号 `+= 1` 只发生在 `[clk] p` 上，`n` 只改相位。原因：**只插桩上升沿是最常见的省事写法**，它必须仍然给出完整可用的周期编号；否则插桩的人会为了"让格式满意"而多写一倍的记录。
- 相位 `p`/`n` 保留是为了跨周期表达的精度（例如"第 3 周期下降沿进入低功耗"）。

### 4.2 位置隐式推进，而不是每条记录都写周期号

每条记录都带 `at=` 会把文件体积放大且让写入者多做事；`clk` 记录本身已经钉住了时间轴。解析器只维护每域两个整数 `(cycle, phase)`，O(1)。

### 4.3 `dom=` 是唯一的域指定方式

早期草案里 `clk` 用位置参数指定域（`[clk] "core", p`），其它类型用 `dom=`。两条规则并存意味着"参数个数决定语义"，是最容易写错、也最容易让解析器分叉的构造。现在统一为 `[clk] p, dom=core`：一条规则贯穿全部 7 种类型。

### 4.4 保持型 vs 瞬时型

- `val` / `fsm` / `pip`（v2.0 起）：**保持型**（采样-保持），语义 = "从此刻起一直是这样"。这符合信号、状态机状态、以及"流水级里现在装着什么"的物理含义，避免每条记录都重发当前值。
- `cnt` / `evt`：**事件型**，语义 = "此刻发生了一件事"。
- 两种语义在 §9 里给出的派生量完全不同（阶梯函数 vs 事件点），因此**不能**用一个通用记录类型糊过去 —— 这正是 `cnt` 与 `evt` 分开的原因，也是 `fsm` 不并入 `val` 的原因（状态机需要跳转表与自环统计）。

### 4.5 `pip`：为什么要"保持型取值"，而不是"进出配对"（v2.0 的决定）

v1.x 的 `pip` 是"`I` 进 / `O` 出 / `X` 撤"的配对模型，由标记匹配、FIFO 兜底。v2.0 换成了
**直接指定该级此刻的新值**（`bubble` 表示变空），没有记录就保持上一值 —— 与 `val` 同构。
换掉的三个理由：

1. **插桩端少写一半**：出口不必再写一条；不需要维护标记唯一性；不需要关心队列顺序。
   真实波形插桩最常见的形态就是"每拍看看这一级里是什么"，落成文本就是一条设值记录。
2. **可视化口径统一**：保持 → 变化 → 气泡，与 `val`/`fsm` 完全同一套读法（§9.3 / §9.5），
   "取值相等的相邻采样合并成一段"这条渲染规则可以直接复用。事实也验证了这一点：
   9 份语料按"净状态"改写后，占用度、气泡、驻留**逐个数字都不变**。
3. **配对模型自己制造了三类麻烦**：`orphan_exit`（凭空出队）、`duplicate_tag`（同标记多条目）、
   以及"队列里谁先出去"这条需要写入者与解析器达成一致的隐规则。保持型模型下它们**整体消失**
   —— 值就是身份，同一个值再写一次只是"还是它"。

代价写在规范 §12.5 里，最要紧的一条：**一个轨道同时只有一个当前值**，队列要用多条轨道表达；
`O`/`X` 之分消失，冲刷与正常离开在数据上不可区分。

保留的口径：占用的仍是半开区间 `[enter, close)`（§4.6）。

### 4.6 半开区间与"同拍设了又改"

占用度定义为 `[enter, close)`：一条在同一拍里被设上又被改掉的条目，驻留为 0 周期，也不计入任何周期的占用度。这对应"组合直通"的物理现实，也避免了"同一拍算不算 1"这种无意义的争议。

### 4.7 跨域条目不报周期延迟

`core` 的 1 个周期与 `mem` 的 1 个周期不是同一个量，`close_cycle - enter_cycle` 跨域相减没有意义。规范选择**拒绝给数**，只给两端位置与 `cross_domain` 诊断；换算成时间需要 `@domain` 的 `period`，那是可视化层的事。

### 4.8 4 态数值

RTL 里有 `x`（未知）、`z`（高阻），仿真早期几乎处处是 `x`。若不支持，插桩就得自己发明编码，解析器也得再翻译一次。因此数值字面量直接采用 Verilog 风格（`4'b10xz`、`32'hDEAD_BEEF`、`'hFF`），并在任何位置接受裸词 `x`/`z` 表示 4 态标量。

### 4.9 版本行：写入者必须写，解析器必须容忍缺失

- 强制写入者写出，是为了让文件自描述（工具能判定版本、能识别文件类型）。
- 要求解析器容忍缺失，是为了让老文件、手写片段、以及 AGENT.md 里的最小示例都能直接解析。缺版本 ⇒ 按 `1.x` 处理。
- 主版本不匹配 ⇒ 默认拒绝：宁可明确报"这个文件我不认识"，也不要按旧规则曲解新语义。

### 4.10 两种容错策略的区分

| 输入 | 策略 | 理由 |
| --- | --- | --- |
| 未知**属性** | 忽略属性，**记录照用** | 属性是纯粹的附加信息，丢掉不影响语义 |
| 未知**类型** | 整行跳过并计数 | 无法解释其语义，硬猜会污染派生量 |
| 未知**指令** | 忽略该行 | 指令只描述文件自身 |
| **非法记录**（语法/类型错） | 跳过该行并计数 | 解析不出来 |
| **语义异常**（orphan、负计数、自环……） | **保留数据**，记录诊断 | 数据是真的，异常是设计者需要看到的信息 |

### 4.11 诊断分级

把"解析错误"与"可能的插桩问题"分开，是因为二者的处理方式不同：前者影响数据完整性，后者影响数据可信度。可视化应当把 §10.4 的诊断显示出来（例如"本轨迹有 3 次凭空出队"），而不是静默吞掉。

### 4.12 gzip 用 `Z_SYNC_FLUSH`

gzip 成员尾部的 CRC/ISIZE 只有在写完整个流时才正确；崩溃时会得到"解压到一半"的流。写入者定期 `Z_SYNC_FLUSH` 可以让已写出的数据成为可解压的完整块 —— 这是把 §10.1 的崩溃安全性质延伸到压缩容器的唯一办法。

### 4.13 异步事件用属性 `async=`，而不是新记录类型或新相位

需求：有些事件不是在时钟沿上采样得到的（外部中断、DMA 完成、异步握手回报、采样器在区间中途读到的计数），可视化应当把它们画在两个时钟沿**之间**，而不是吸附到沿的刻度上。

决策与理由：

| 方案 | 评价 |
| --- | --- |
| **属性 `async=1`（采用）** | 它只描述"采样方式"，与记录语义正交：位置模型、延迟、占用度、保持型语义全都不用改；老解析器按 §10.2 忽略未知属性后，文件**仍然完全可解析**（只是画法退化），不影响 1.x 兼容 |
| 新记录类型 `[async]` | 描述的是同一件事的另一种说法，会让"计数/数值/轨道"都要各来一份异步版本 |
| 新相位字母（如 `p'`/`mid`） | 相位属于时间模型：加"半相位"就要重新定义周期编号、`state_at`、占用度的坐标轴，收益却只是画法 |
| 位置里加精确偏移（`at=12.3p`） | 那需要亚周期时间语义；用户当前要的是"画在两个沿之间"，不是"精确到 ns"。留作 v1.1 的 `frac=` |

配套的硬性约定：

- 缺省**必须**是沿对齐（缺省即同步）：绝大多数插桩就写在时钟沿里，缺省要服务最常见写法。
- `clk` 上出现 `async=1` 自相矛盾（时钟沿的定义就是"沿"）⇒ 忽略属性 + `async_on_clk` 诊断，**不**丢弃这条沿。
- `async` 事件仍占据确定的 `(域, 周期, 相位)` 区间，因此它照常计入该周期的计数增量、照常参与延迟与占用度 —— 规范不允许它"半周期"地介于两个周期之间，否则派生量就不再唯一。
- `msg` 不支持属性，所以没有"异步 msg"；需要异步注解就用 `evt` + `note=`。

### 4.14 写入者必须按位置非递减输出

这条从"应当"升级为"必须"是解析器优先的直接结果：单调性保证解析器可以边读边出结果，不必缓存整个文件来重排。后处理工具需要乱序补写时，用 `at=` 显式定位，并在规范里明确"带 `at=` 的文件不保证单调"。

## 5. 被否决的方案

| 方案 | 否决理由 |
| --- | --- |
| 二进制/位打包记录 | 违反"文本格式"的硬要求；且变长编码破坏前缀封闭 |
| 差分/增量编码（"与上一行相同则省略"） | **破坏前缀封闭**：丢一行会连锁失真 |
| 符号表/字典（v1.0） | 值得做，但要求"定义先于使用"才能保住前缀封闭；v1.0 先内联名字，留作 v1.1 的第一优先级（§12.4） |
| 每行多条记录 | 截断粒度变粗，一行坏掉损失多条 |
| FSM 并入 `val` | 丢失跳转表/自环/驻留等专用派生量 |
| `pip` 用"计数增减"代替取值 | 只能得到占用度曲线，答不出"第 N 周期的输入第 N+M 周期才出来"。（v2.0 换成的是**取值**而非计数：每一段都是完整的 `[enter, close)`，所以驻留分布照旧拿得到 —— 见 §4.5） |
| 绝对时间戳（wall-clock） | 仿真时间由周期定义；wall-clock 受宿主机负载影响，不可复现 |
| 记录用 JSON 对象表达 | 体积、解析开销、浮点与大整数语义都不划算；且无法一行为一条记录地保持可读 |
| 把 `msg` 做成结构化事件 | `msg` 是给人看的注解，解析器只需按原文收下，不需要语义 |

## 6. 已知代价与风险

1. **名字重复**：同一轨道名在每个条目上重复出现，大轨迹里名字占多数字节。缓解：gzip；根治：v1.1 的字典（§12.4）。
2. **文本数值解析**：每行要扫一遍数字。相对仿真本身的开销可忽略，但在 TB 级后处理时值得做零拷贝解析。
3. **没有 schema 校验**：规范不知道"这个设计应该有哪些轨道"。写错名字会静默生成两条轨迹（`undeclared_domain` 只能挡住域名的拼写错误）。缓解：W5 要求名字稳定；工具可以做"名字集合"的回归比对。
4. **不含依赖/握手语义**：`pip` 只能表达"每一级此刻持有什么"，表达不了"这条指令在等那条指令的结果"，也表达不了"一个逻辑操作拆成多条轨道记录"（AXI 突发、4KB 拆分）与"同一请求的多次占用"（重试）。这是 `ref=`/`dep` 要解决的。
5. **单文件单事件流**：不支持一个文件里放多个互不相关的轨迹（多核会话就是一条流 + 多个域，够用；但"多份仿真合并"需要外部工具）。
6. **`at=` 的门槛**：它让"位置单调"这条保证变为有条件（且是**每域**单调），解析器必须检查是否出现过 `at=`。换来的价值是采样器与后处理工具不必伪造 `clk` 记录。
7. **取值就是身份，也仅此而已**（v2.0 起）：同一条轨道连续持有同一个值会被算作**一个**条目，
   所以"同一条内容第二次进入该级"与"它还待在那里"在数据上不可区分；要区分必须改变取值
   （例如把序号编进值里）。同理，一个轨道同时只有一个当前值 —— 队列要用多条轨道表达（§12.5）。

### 6.1 规模实测（决定 v1.1 优先级的那组数字）

在合成轨迹上实测（Python3 / WSL2 / gzip -6，1e6 条记录）：

| 指标 | 值 |
| --- | --- |
| 平均记录长度 | ≈ 33.7 B |
| gzip -6 压缩比 | 6.0×（内容随机）～ 29.1×（高度重复） |
| 逐行 tokenize + 名字驻留 | 2.89M 记录/s ≈ 97 MB/s |
| 同上，走 gzip 流式解压 | 2.53M 记录/s ≈ 85 MB/s |

外推：1e8 条记录 ≈ 3.4 GB 文本、gzip 后 0.12~0.56 GB，单遍语义解析 35~40 s（Python 级；C/Rust 约 10 s 级）；1e9 周期 × 5 个域、每个沿一条 `[clk]` ≈ 95 GB 文本。

结论：**文本 + gzip 在 1e8 量级可用，1e9 量级必须靠字典压缩**，这也是 `@sym` 被列为 v1.1 第一优先级的原因。同时规范只承诺"单遍、有界内存"，不承诺可寻址 / 可随机查询（gzip 不可 seek）。

## 7. 演进路线

按"新增属性 → 新增类型 → 新增指令"的优先级（§12.2）：

| 版本 | 项 | 说明 |
| --- | --- | --- |
| v1.1 | 符号字典 `@sym` + 短标识引用 | 体积与吞吐的最大杠杆（见 §6.1 实测）；约束是定义先于使用 |
| v1.1 | `ref=`：条目引用 | 补上"条目中间里程碑"（ROB 的 complete、MSHR 的 merge、总线 grant）与"同一逻辑操作多次占用轨道"（重试、4KB 拆分）——探针里四个场景中的三个都撞在同一处 |
| v1.1 | `@track depth=` / `@group width=` | 只有绝对占用度，算不出利用率、并行端口组也表述不了（双发射、32 深 ROB、8 条 MSHR、4 bank 全部命中） |
| v1.1 | `frac=`（0~1 的区间内偏移） | `async=1` 只说"在区间内部"，不说具体偏移；要精确到 ns 就得落回两条沿之间 |
| v1.1 | `reason=` 属性 | 撤销/失败原因（端口冲突、冲刷、取消、命中/未命中）机器可读，现在只能塞 `note=` |
| v1.1 | `unit=` 属性 | 机器可读地标注比率类数值（IPC、命中率）；键名已预留 |
| v1.1 | `stall`：停顿建模 | 记录"某级因何停顿"，与 `pip` 占用度为 0 的气泡互补 |
| v1.2 | 区间/测量段 | 对一段周期做聚合统计（窗口 IPC、区段 stall 分布），并给 `cnt`/`evt` 归组 |
| v1.2 | `dep`：依赖边 | 记录指令间的寄存器/内存依赖，用于关键路径分析 |
| v2.0（讨论稿） | 列式/二进制容器 | 只在 TB 级长期归档场景下才有必要；会带来第二种解析器 |

`ref=` 的硬约束是"只能引用已经出现过的条目"：否则解析器要么无法解析，要么必须缓存全部历史条目，违背 §13.2 第 10 条的有界内存承诺。

## 8. 评审驱动的 v1.0 修正

三份独立评审（规范可实现性、示例推导复算、四个微架构场景的表达力探针）驱动了下列 v1.0 定稿修正。全部是**定义澄清**或**诊断新增**，没有引入新语法：

| 修正 | 来源 | 性质 |
| --- | --- | --- |
| "位置非递减"改为**每域独立**约束，跨域顺序只由文件顺序定义 | 探针（4 核场景）：跨域位置不可比较，原规则让多域文件无法判定合规 | 定义缺陷（阻断级） |
| 新增 `latency_time`：两域都声明 `period` 时给出跨域条目的时间延迟 | 同上：原规范禁止跨域给周期延迟，却没给替代量 | 定义缺口 |
| 跨域条目的占用度按 `enter` 域统计 | 同上：多域下占用度曲线原本不可复现 | 定义缺口 |
| §10.7 第 3 条改为"**可流式地**报告全部事件"，并禁止要求物化 | 探针：与 §13.2 第 10 条的流式承诺字面冲突 | 文档矛盾 |
| 派生量明确为**函数**，允许按需/稀疏/直方图表示 | 探针：1e10 量级的逐周期表不可能物化 | 定义澄清 |
| 新增 `duplicate_tag` 诊断 + 标记唯一性要求 | 探针（ROB/内存控制器）：同标记多条目会静默错配，延迟统计直接错 | 静默失真 → 诊断 |
| 新增 `undeclared_domain` 诊断 | 探针（多核）：`dom=cor1` 拼写错误会静默新建时间轴 | 静默失真 → 诊断 |
| 新增 `at_clk_conflict` 诊断 | 探针（采样场景）：混用 `clk` 与 `at=` 会让位置与周期计数脱节 | 静默失真 → 诊断 |
| 禁止按运行时对象动态命名（`"core.mshr[M2]"` 之类） | 探针：这类名字让追踪对象数随仿真时间增长，破坏有界内存 | 明确禁止的 hack |
| 同周期撤销的条目只计入 `aborts`，不进占用度与延迟分布 | 探针：原表述只在"进出"上说了，撤销情形没写 | 边界澄清 |
| 明确 clk-free 模式是合规写入者（采样器/后处理），并给出其附加条件 | 探针（采样场景）：真实采样器产出的文件原本既不合规也不被禁止 | 合规性缺口 |
| 新增 `delta_between`/区间速率，并禁止用 `val` 重写比率 | 探针（采样场景）：`abs=` 回读的核心运算原本没有定义 | 定义缺口 |
| `period = 1/freq` 的换算补进 §8.2 | 推导复算：`freq=` 只说了"以 period 为准"，没给换算 | 定义缺口 |
| 示例 §1 的 `IF` 占用度 `c1` 由 1 改为 0 | 推导复算：半开区间下同周期进出不计占用度 | 文档错误 |

### 8.1 v2.0：`pip` 改为保持型取值（不兼容）

| 变更 | 来源 | 性质 |
| --- | --- | --- |
| `[pip] <轨>, <方向>[, <标记>]` → `[pip] <轨>, <值\|bubble>`；没有记录则保持上一值 | 用户决定：插桩端"每拍直接给这一级的取值"最省事，且与 `val` 同构 | **主版本 +1**（§12.1） |
| 删除方向 `I`/`O`/`X`、标记匹配、FIFO 兜底 | 保持型模型下"值变了就是新条目"，不再需要配对 | 语法与语义删减 |
| 删除诊断 `orphan_exit`、`duplicate_tag` | 二者都是配对模型的产物 | 诊断删除 |
| 新增诊断 `pip_legacy_direction` | 旧文件里的 `I`/`O`/`X` 必须给出一条**指得明白**的迁移提示 | 迁移辅助 |
| `PipelineItem.exit`/`abort`/`closed`/`orphan` → `close`；`tag` → `value`；`TrackInfo.completed`/`aborted`/`orphan`/`aborts`/`duplicateTags` → `closed`/`open` | 派生量随语义重建 | 派生量重命名 |
| `latency_cycles` 的含义由"入到出"变为"驻留"（数值口径不变，仍取 `[enter, close)`） | 同上 | 定义重述 |
| 9 份语料 + 内置示例按"每级净状态"改写，版本行升到 `2.0` | 同上 | 数据迁移 |

迁移后的对照验证：占用度表（60 格逐格）、气泡区间、跨域 `latency_time`、未闭合条目 —— 与 v1.x 的期望值**逐个一致**；
新增进延迟分布的是原先被 `X` 撤掉的 2 条（v2.0 不区分结束原因，spec §12.5）。

## 9. 待定（需要拍板）

1. 是否在 v1.1 引入符号字典？（收益明确，代价是"定义先于使用"这条额外约束与一次间接层。）
2. 是否在 v1.1 引入 `ref=`？（它一条覆盖"里程碑 / 重试 / 拆分 / 仲裁归因"四个探针缺口，但需要同时确定"引用已闭合条目"的解析策略。）
3. `@domain` 的 `period`/`freq` 是否值得保留？它只服务于时间轴换算，但跨域延迟换算成 ns 必须有它（见新加的 `latency_time`）。
4. 是否需要"容量"声明（`@track depth=`）？否则利用率类指标在规范内不可定义。
5. 是否需要一条"强校验模式"：写入者声明"我只使用 1.0 的记录类型"，解析器遇到未知类型即报错，而不是静默跳过。（现在未知类型永远是跳过 + 计数。）
